# focusflow · 功能 PRD
## 闪念收集盒（Inbox）& 回神引导

**版本**: v1.0
**日期**: 2026-04-26
**所属产品**: focusflow Windows 桌面端
**依赖**: MVP 核心功能（任务列表、快速记录、番茄钟）

---

## 一、背景与问题

用户在专注工作时，大脑会不断冒出与当前任务无关的想法——「要回那条消息」「突然想到一个点子」「好像还有件事没做」。

这类想法有两个特点：**不记下来会忘，记下来的动作本身会打断专注**。

现有的快速记录功能解决了「不遗忘」，但还有两个断层没有处理：

**断层一：记录时需要判断**。当前记录直接进任务列表，用户潜意识里会想「这算任务吗？分什么类？」这个判断本身消耗认知资源，增加了记录的门槛和中断时长。

**断层二：记录后没有回神机制**。想法记完之后，用户停在记录的心理状态里，没有东西把注意力拉回当前任务，大脑容易继续停留在刚才的想法上。

这两个问题共同导致：一次记录打断专注的时间，远超「输入几个字」本身的物理时长。

## 二、功能一：闪念收集盒（Inbox）

### 2.1 核心设计

在快速记录输入框下方增加一个切换开关，将记录目标分为两个池子：

- **任务池**（现有）：有明确意图要做的事，进入任务列表，需要选分类和优先级
- **Inbox**（新增）：先扔进去再说，零判断，不需要分类，不出现在任务列表里

两个池子的切换方式：默认进 Inbox，按 `Tab` 键切换到任务池，界面有轻微颜色变化提示当前目标。专注模式下，输入框默认且只能进 Inbox，强制用户不在专注时处理和判断。

核心原则：**Inbox 的门槛必须比任务池更低**，低到「想到什么直接按快捷键打进去就走」。

### 2.2 用户流程

**收集阶段（专注中）**
```
想法冒出来
    ↓
Ctrl + Space 唤起输入框（自动聚焦，默认 Inbox 模式）
    ↓
打字，Enter
    ↓
界面显示「已存入收集盒」（0.8 秒后消失）
    ↓
窗口自动收起，回到工作
```

**处理阶段（每日结束时）**
```
番茄钟当日最后一个休息期 / 用户手动打开收集盒
    ↓
逐条查看 Inbox 内容
    ↓
每条选择：
    → 转为任务（进任务列表，此时补充分类）
    → 存档（保留记录但不转任务，归入「想法库」）
    → 删除（当时想想，现在觉得不重要）
    ↓
清空完成，当日 Inbox 归零
```

### 2.3 UI 设计

**输入框形态变化**

Inbox 模式（默认）：
```
┌─────────────────────────────────────────┐
│  ◎  随手记，不用想太多...          收集盒 │
└─────────────────────────────────────────┘
```

任务模式（Tab 切换后）：
```
┌─────────────────────────────────────────┐
│  ✦  添加一条任务...                任务 ↓│
└─────────────────────────────────────────┘
```

两种模式的视觉区别：Inbox 模式边框为蓝色调，任务模式边框为紫色调，右侧标签文字不同。切换时有 100ms 颜色过渡，不突兀。

**Inbox 入口**

窗口底部 stats 栏右侧新增一个小图标，显示当日 Inbox 未处理数量：
```
[0 完成]  [3🔥 连续]  [0 XP]  [◎ 4]
```
点击打开 Inbox 处理面板。

**Inbox 处理面板**

从窗口底部向上展开，覆盖任务列表区域：

```
╔═══════════════════════════════════════╗
║  ◎ 收集盒  ·  4 条待处理             ║
╠═══════════════════════════════════════╣
║                                       ║
║  回复林老师的消息                      ║
║  [→ 转任务]  [存档]  [删除]           ║
║  ─────────────────────────────────   ║
║  那个关于定价策略的想法               ║
║  [→ 转任务]  [存档]  [删除]           ║
║  ─────────────────────────────────   ║
║  买猫粮                               ║
║  [→ 转任务]  [存档]  [删除]           ║
║  ─────────────────────────────────   ║
║  可以做一个用户访谈                   ║
║  [→ 转任务]  [存档]  [删除]           ║
║                                       ║
╠═══════════════════════════════════════╣
║  [全部删除]            [稍后再说]     ║
╚═══════════════════════════════════════╝
```

章章在面板顶部显示台词：「来清理一下今天的想法吧，清空之后更轻松～」

### 2.4 Inky联动

- Inbox 每存入一条：嘴里吐出一个小泡泡（呼应泡泡阶段的形态设计），泡泡里有一个小点，表示「帮你记住了」
- Inbox 清空后：做出「伸懒腰」动作，台词「清空了！脑子轻多了吧？」
- Inbox 积压超过 8 条未处理：章章表情变成「有点担心」，台词「收集盒快装满了，找个时间整理一下？」（每天最多提示一次，不烦人）

### 2.5 数据模型

```
InboxItem {
  id: string
  text: string
  created_at: timestamp
  status: 'pending' | 'converted' | 'archived' | 'deleted'
  converted_task_id: string | null   // 转任务后关联
  date: string                       // YYYY-MM-DD
}
```

### 2.6 验收标准

- [ ] 专注模式下输入框默认且只能进 Inbox，无法切换到任务模式
- [ ] 非专注模式下 Tab 键可切换两种模式，有视觉反馈
- [ ] Inbox 存入后窗口自动收起，全流程 ≤ 3 秒
- [ ] 处理面板可逐条操作，「转为任务」后自动补充分类选择
- [ ] 处理完所有条目后面板自动关闭，触发章章清空动画
- [ ] Inbox 数量角标实时更新

## 三、功能二：回神引导

### 3.1 核心设计

每次记录（Inbox 或任务）提交后，界面短暂显示一条「锚定提示」，用当前任务名把用户注意力拉回来，1.5 秒后自动消失，不需要任何操作。

设计原则：**存在感要轻，但锚点要具体**。不是「记好了，继续加油！」这种空洞的鼓励，而是「已记下 → 当前任务名」，用具体的任务名做钩子。

### 3.2 触发条件

| 场景 | 是否触发回神引导 |
|------|----------------|
| 专注模式中记录 Inbox | ✅ 触发，锚定到当前绑定任务 |
| 专注模式中记录任务 | ✅ 触发，锚定到当前绑定任务 |
| 非专注模式记录 | ❌ 不触发（没有在专注，不需要拉回） |
| 处理 Inbox 转为任务 | ❌ 不触发 |

只在专注模式中有意义，其他场景不触发，避免引导变成噪音。

### 3.3 UI 设计

**回神提示条**

记录提交后，在输入框正下方出现一条提示，动画为从输入框向下 slide in（100ms），停留 1.5 秒，fade out（200ms）：

```
  ✓ 已存入收集盒  ·  回到 → 整理读书笔记第三章
```

样式：
- 背景透明，无边框
- 左侧「✓ 已存入收集盒」为浅灰色
- 分隔符「·」为更浅的灰
- 「回到 →」为浅灰
- 任务名为白色，字重稍粗，是整条提示里最醒目的部分
- 整体字号 11px，不抢眼但清晰可读

**不同场景的文案**

| 记录目标 | 提示文案 |
|---------|---------|
| 存入 Inbox | `✓ 已存入收集盒  ·  回到 → {任务名}` |
| 添加任务 | `✓ 已加入任务列表  ·  回到 → {任务名}` |
| 任务名超过 16 字 | 截断显示，加省略号 |

**边界情况**：若用户在提示消失前再次记录，上一条提示立即消失，新提示重新出现，不叠加。

### 3.4 章章联动

回神提示出现的同时，章章做一个极轻的「转头看你」动作（眼睛方向微调，帧动画 2 帧），像在说「记好了，我们继续」。动作幅度非常小，1 秒内完成，不抢注意力。

### 3.5 用户设置

在设置页新增一个开关：「专注时显示回神引导」，默认开启。部分用户可能觉得任何弹出都是干扰，给他们关掉的选项。

### 3.6 验收标准

- [ ] 仅在专注模式中触发，非专注模式记录后无提示条出现
- [ ] 提示条 1.5 秒后自动消失，不需要用户操作
- [ ] 任务名超长时正确截断
- [ ] 连续快速记录时，提示正确刷新，不叠加
- [ ] 设置关闭后完全不出现
- [ ] 提示出现和消失的动画流畅，无卡顿

## 四、两个功能的协同效果

单独来看，Inbox 解决「记录时不用判断」，回神引导解决「记录后回到专注」。两个功能结合，完整覆盖了一次「专注中冒出想法」的全流程：

```
想法冒出来
    ↓
Ctrl + Space（快捷键，不离开当前工作区域）
    ↓
打字，Enter（零判断，默认 Inbox，3 秒内完成）
    ↓
「✓ 已存入收集盒  ·  回到 → 整理读书笔记」（锚点拉回注意力）
    ↓
窗口收起，回到工作（想法安全，注意力回来了）
```

用户在这个流程里做的决策只有一个：「按不按快捷键」。其他所有判断都被延迟到休息时或当日结束时，彻底保护专注期间的注意力资源。

## 五、对现有功能的影响

| 现有模块 | 变化 |
|---------|------|
| 快速记录输入框 | 新增 Inbox / 任务切换逻辑，默认行为改为进 Inbox |
| 任务列表 | 不变，Inbox 内容不出现在列表里 |
| 番茄钟专注模式 | 强制 Inbox 模式，屏蔽任务模式切换 |
| 底部 stats 栏 | 新增 Inbox 数量角标 |
| 设置页 | 新增「专注时显示回神引导」开关 |
| 数据模型 | 新增 `InboxItem` 表，`settings` 表新增 `show_focus_return` 字段 |

原有任务流程、XP 系统、章章升级机制**完全不受影响**。

---

## 六、发布建议

两个功能建议**捆绑在同一个版本**发布，分开发布会让用户感受到功能不完整——Inbox 没有回神引导时，用户记完想法还是会停留；回神引导没有 Inbox 时，锚点提示的意义不大。

建议在 MVP 核心功能稳定后作为 **v1.1** 发布，作为「专注保护」功能组合进行宣传，和竞品形成明显区隔。
