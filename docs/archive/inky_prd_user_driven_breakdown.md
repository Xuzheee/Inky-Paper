# Inky · 用户主导任务拆解 PRD
**版本**: v1.0
**日期**: 2026-04-26
**所属产品**: Inky Windows 桌面端
**依赖**: MVP 任务列表、番茄钟任务绑定

---

## 一、功能定位

### 核心思路

用户自己描述完成任务的计划，AI 把自然语言整理成结构化子任务列表。

这和纯 AI 拆解的本质区别是：**内容来自用户，AI 只做格式化**。用户已经知道怎么做，只是需要一个工具把脑子里的计划「落地」成清单。准确率接近 100%，因为 AI 不需要创造内容，只需要理解和整理。

### 解决的问题

ADHD 用户经常有一个现象：脑子里其实有计划，但计划是模糊的、散的，停留在「大概知道怎么做」的状态，没有变成可以一步步执行的清单。这个中间的转化成本——把脑子里的想法变成纸面上的步骤——足以让人放弃开始。

Inky 把这个转化成本压到最低：用户只需要像跟朋友说话一样描述一下计划，剩下的 Inky 来做。

## 二、用户流程

### 主流程

```
用户在任务列表点击某条任务右侧的「✦」按钮
        ↓
弹出计划输入卡片
用户用自然语言描述自己的计划
        ↓
点击「整理成步骤」或按 Enter 提交
        ↓
输入卡片进入加载状态（Inky 思考表情，约 1 秒）
        ↓
弹出确认卡片，展示 AI 整理好的子任务列表
用户可直接修改任意一条
        ↓
点击「确认，开始」或按 Enter
        ↓
子任务折叠展开在原任务下方
卡片关闭，Inky 轻跳 + 台词
```

### 分支流程一：用户不知道怎么做

计划输入卡片底部有一个次要按钮「还不知道怎么做」，点击后关闭当前卡片，Inky 给出一条引导台词：「没关系，先把任务拆小一点？告诉我这件事大概要做什么～」并聚焦到输入框，引导用户至少说出一个大方向，再走同样的整理流程。

### 分支流程二：用户对结果不满意

确认卡片上有「重新描述」按钮，点击后返回输入卡片，保留上次的输入内容供用户修改，而不是清空重来。

### 分支流程三：AI 解析失败 / 超时

超过 5 秒未返回，静默降级：关闭加载态，展示空的子任务输入框，Inky 台词「Inky 没听清楚，你直接写步骤也行～」。用户可以手动逐条输入子任务。

## 三、UI 设计

### 3.1 触发入口

任务列表每条任务右侧显示「✦」图标，hover 时出现「拆解计划」文字提示。已拆解过的任务图标变为「✦·」。已完成任务不显示该图标。

```
┌──────────────────────────────────────┐
│  ○  复习数学第一章          [学习] ✦ │
│  ○  回复导师邮件            [工作] ✦ │
│  ○  买明天早饭              [生活] ✦ │
└──────────────────────────────────────┘
```

### 3.2 计划输入卡片

从「✦」按钮位置向上弹出，宽度与悬浮窗等宽，背景深色，紫色描边：

```
╔══════════════════════════════════════╗
║  🐙  复习数学第一章                  ║
║  你打算怎么做？                      ║
╠══════════════════════════════════════╣
║                                      ║
║  ┌────────────────────────────────┐  ║
║  │                                │  ║
║  │  在这里用自己的话描述计划...   │  ║
║  │                                │  ║
║  └────────────────────────────────┘  ║
║                                      ║
║  比如：先看第一节，再做课后题         ║
║                                      ║
╠══════════════════════════════════════╣
║  [还不知道怎么做]      [整理成步骤 ↵]║
╚══════════════════════════════════════╝
```

**细节**：
- 卡片打开后输入框自动聚焦
- placeholder 每次随机显示一条示例，让用户明白输入格式
- 输入框高度自适应内容，最小 3 行最大 8 行
- 「整理成步骤」按钮在输入框有内容时才高亮可点击

**示例 placeholder 池**（随机取一条）：
```
先看第一节，再做课后题，最后总结笔记
打开文档写大纲，然后逐节展开，最后检查一遍
先回顾上次写到哪，今天完成第三节
收集需要的资料，整理成文档，发给老师
```

### 3.3 加载状态

点击「整理成步骤」后，输入卡片原地切换为加载态，不跳转：

```
╔══════════════════════════════════════╗
║  🐙  Inky 正在整理...               ║
╠══════════════════════════════════════╣
║                                      ║
║         ● ● ●                        ║
║                                      ║
╚══════════════════════════════════════╝
```

Inky 同步切换为「思考」表情（眼睛变 ◉◉）。

### 3.4 确认卡片

加载完成后，输入卡片过渡为确认卡片：

```
╔══════════════════════════════════════╗
║  ✦ 整理好了，看看对不对？            ║
╠══════════════════════════════════════╣
║                                      ║
║  1.  打开课本，找到第一章            ║
║  2.  阅读第一节，圈出重点知识        ║
║  3.  阅读第二节，同样标注重点        ║
║  4.  完成第一章课后习题              ║
║  5.  用自己的话写一段总结            ║
║                                      ║
║  点击任意一条可以直接编辑            ║
║                                      ║
║  Inky：「计划很清晰！先打开课本开始？」║
╠══════════════════════════════════════╣
║  [重新描述]            [确认，开始！]║
╚══════════════════════════════════════╝
```

**可编辑**：点击任意一条文字，该行变为输入框，用户修改完按 Enter 或点击其他区域确认。支持删除某条（行尾出现 ✕）和拖拽排序。

**不展示**：预估时长、优先级、分类标签，保持简洁。

### 3.5 任务列表展开态

确认后卡片关闭，原任务下方展开子任务：

```
┌──────────────────────────────────────────┐
│  ○  复习数学第一章           [学习]  ✦· │
│     │                                    │
│     ├─  ○  打开课本，找到第一章          │
│     ├─  ○  阅读第一节，圈出重点知识      │
│     ├─  ○  阅读第二节，同样标注重点      │
│     ├─  ○  完成第一章课后习题            │
│     └─  ○  用自己的话写一段总结          │
│                                          │
│  ○  回复导师邮件             [工作]  ✦  │
└──────────────────────────────────────────┘
```

**展示规则**：
- 子任务默认展开，点击原任务行可折叠，折叠后显示「▸ 5 个步骤 · 已完成 2 个」
- 子任务复选框 11px，比主任务（13px）略小，颜色略浅
- 子任务行右侧 hover 时出现「▶」番茄钟绑定按钮和「✕」删除按钮
- 子任务列表底部有「+ 手动添加步骤」入口

## 四、Inky 联动

| 时机 | Inky 表情 | 台词 |
|------|----------|------|
| 打开输入卡片 | 正常 | 无台词，不打扰输入 |
| 加载中 | 思考（◉◉） | 无台词 |
| 确认卡片出现 | 开心 | 「计划很清晰！先从第一步开始？」|
| 用户点「确认，开始」| 跳动 | 「步骤都在了，第一步随时可以开始 ✦」|
| 完成第一条子任务 | 跳动 | 「开始了！最难的是第一步，你做到了」|
| 完成所有子任务 | 大跳 + 星星眼 | 「全部步骤搞定！记得给主任务打个勾～」|
| 输入描述为空点提交 | 正常 | 「说说你打算怎么做？随便说都行～」|
| AI 解析失败 | 困惑 | 「Inky 没听清，你直接写步骤也行～」|

## 五、Prompt 设计

### System Prompt

```xml
<system>
你是 Inky 的计划整理引擎。用户描述了自己完成一个任务的计划，
你需要把口语化的描述整理成清晰、可执行的子任务列表。

<rules>
# 核心原则
用户说什么，你整理什么。不增加用户没有提到的步骤，不删除用户提到的内容。
唯一允许做的是：把模糊的表达补全成「动词 + 具体对象」的结构。

# 步骤边界识别
以下词语标志步骤切分点，遇到时新开一条子任务：
先/然后/再/接着/之后/最后/第一/第二/第三/最终/完成后/做完后

# 补全规则
模糊动词 → 具体动作：
- 「复习第一章」→「阅读第一章，标注不懂的地方」
- 「看一下邮件」→「打开邮件客户端，阅读邮件内容」
- 「整理一下」→「整理[用户描述的对象]，分类归档」
- 「做习题」→「完成[科目]课后习题」

# 数量控制
- 最少 2 条，最多 6 条
- 如果用户描述的步骤超过 6 个，合并相似或相邻的小步骤
- 如果用户描述只有 1 个步骤，拆成 2 条（开始 + 完成）

# 格式规则
- 每条不超过 20 字
- 用中文输出，即使用户用英文描述
- 不加编号前缀（编号由前端渲染）
- 不加「第一步：」「步骤一：」等标记

# 禁止内容
- 不输出「思考」「计划」「准备」等纯认知动词
- 不输出超过 20 字的步骤
- 不增加用户没提到的检查、优化、复盘等步骤

# Inky 台词
一句话，轻松口吻，≤15 字，带一个颜文字。
根据任务类型调整：
- 学习类：鼓励开始，不说教
- 工作类：轻松务实
- 生活类：简单直接
</rules>

<examples>
<example>
<task>复习数学</task>
<user_plan>先复习第一章，再复习第二章，最后完成习题</user_plan>
<output>
{
  "steps": [
    "打开课本，翻到第一章",
    "阅读第一章，标注重点和不懂的地方",
    "阅读第二章，同样标注重点",
    "完成第一二章课后习题"
  ],
  "inky_comment": "计划很清晰！先翻开课本开始？(ง •̀_•́)ง"
}
</output>
</example>

<example>
<task>写项目汇报</task>
<user_plan>先把上周的数据整理一下，然后写报告，最后检查格式</user_plan>
<output>
{
  "steps": [
    "打开数据文件，整理上周数据",
    "新建文档，按模板写汇报内容",
    "检查格式和数据是否正确"
  ],
  "inky_comment": "三步搞定！先打开数据文件 ٩(◕‿◕｡)۶"
}
</output>
</example>

<example>
<task>回复导师邮件</task>
<user_plan>看一下导师发的邮件，然后回复</user_plan>
<output>
{
  "steps": [
    "打开邮件，阅读导师的邮件内容",
    "写回复，发送"
  ],
  "inky_comment": "简单！先打开邮件看看 (｀・ω・´)"
}
</output>
</example>
</examples>

返回格式（严格 JSON，不加 markdown 代码块）：
{
  "steps": ["步骤文字", "步骤文字", ...],
  "inky_comment": "台词（≤15 字，带颜文字）"
}
</system>
```

## 六、数据模型

### 新增表：sub_tasks

```typescript
SubTask {
  id: string
  parent_task_id: string      // 关联原任务
  text: string                // 子任务文字
  done: boolean
  created_at: timestamp
  done_at: timestamp | null
  order: number               // 排序，支持拖拽调整
  source: 'ai' | 'manual'    // AI 生成还是用户手动添加
}
```

### Task 表新增字段

```typescript
Task {
  ...existing fields
  has_subtasks: boolean        // 控制「✦」变「✦·」
  subtask_count: number
  subtask_done_count: number
}
```

## 七、XP 规则

| 行为 | XP |
|------|----|
| 完成一条子任务 | +5 |
| 完成原任务（无论子任务是否全完成）| +10 |
| 完成原任务且全部子任务已完成 | 额外 +10 |

单任务完整走完所有步骤的最大 XP：5×6 + 10 + 10 = **50 XP**。

## 八、边界情况处理

| 情况 | 处理方式 |
|------|---------|
| 用户输入为空，点击提交 | 按钮保持禁用，不触发请求 |
| 用户输入少于 5 字 | 提交后 Inky 问「能说得再具体一点吗？」，不发起 API 请求 |
| 用户输入超过 200 字 | 截断到 200 字，输入框底部提示「已达最大长度」|
| AI 返回步骤超过 6 条 | 前端截断，只展示前 6 条 |
| AI 返回步骤只有 1 条 | 正常展示，不强制拆多 |
| API 超时（5 秒）| 降级展示空的子任务输入框，Inky 台词引导手动输入 |
| 重复拆解已有子任务的任务 | 确认卡片顶部提示「已有 X 个步骤，确认后会替换」|
| 用户删除所有子任务 | has_subtasks 重置为 false，「✦·」变回「✦」|
| 网络不可用 | 同超时降级处理 |

## 九、验收标准

### 功能验收
- [ ] 点击「✦」按钮正确弹出计划输入卡片，输入框自动聚焦
- [ ] 输入框为空时「整理成步骤」按钮不可点击
- [ ] 输入内容后提交，正确进入加载态，Inky 切换思考表情
- [ ] 确认卡片展示 AI 整理的步骤，每条可点击编辑
- [ ] 确认后子任务正确折叠展开在原任务下方
- [ ] 子任务可独立打勾完成，XP 正确增加
- [ ] 全部子任务完成后原任务复选框轻闪提示
- [ ] 完成全部子任务再完成原任务，额外 +10 XP 正确触发
- [ ] 已拆解任务的「✦」变为「✦·」
- [ ] 重新拆解时有替换提示
- [ ] 超时降级后可手动输入子任务

### 性能验收
- [ ] API 响应 P50 ≤ 1.5s，P95 ≤ 4s
- [ ] 超时兜底在 5s 准时触发
- [ ] 卡片展开/收起动画 ≤ 150ms

### 体验验收
- [ ] 输入卡片 placeholder 随机切换，不每次都一样
- [ ] 确认卡片的 Inky 台词和任务内容相关，不是固定文案
- [ ] 加载过程无布局跳动
- [ ] 全程可纯键盘操作（Tab 导航，Enter 确认，Esc 关闭）

## 十、发布建议

作为 **v1.2** 发布，主题「告诉 Inky 你的计划，她帮你整理好」。

上线后监控两个核心指标：
- **拆解使用率**：有子任务的任务占总任务比例，目标首月 ≥ 30%
- **第一步启动率**：生成子任务后 30 分钟内完成第一条的比例，目标 ≥ 50%

第二个指标最关键——它直接衡量这个功能有没有真正降低启动阻力，而不只是让用户多了一个整理清单的工具。
