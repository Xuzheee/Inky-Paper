# P0/P1 数据升级与恢复

本轮开发和验收只使用新建合成测试库。以下说明正式使用时的行为，不代表本轮读取、升级或恢复过用户正式数据库。

## 升级行为

正式 Paper 数据位于 `%APPDATA%\com.inky.paper`；旧版 Inky-app 的目录、数据库和连接完全独立。

已有 schema 0 的 `paper.sqlite3` 首次由新版打开时，先通过 SQLite 一致性快照生成同目录的 `paper.sqlite3.pre-schema-1.sqlite`。该快照包括已提交的 WAL 数据；只有完整性检查、内容比对成功后，才标记 schema 1。已有备份不会被覆盖。备份失败、备份期间数据变化或未知更高版本都会拒绝升级，不继续修改版本标记。

新增的截止、项目、日预算、偏好、整理状态、父任务确认和总结依据有兼容默认值。历史任务、计时、原步骤快照和个人 Markdown 不因读取新字段而被重写成另一套记录。总结读取凭据是进程连接内的临时元数据，重启后需要重新读取再生成新总结，已提交原请求仍可幂等核实。

## 保留数据

更换可执行文件前，先正常保存本轮并从托盘退出。在应用退出后，保存整个 Paper 数据目录副本，包括数据库、仍存在的 `-wal/-shm` 文件、`工作记录` 中的个人笔记和 `workbench` 对话目录。需要保留未发送或待核实草稿时，也保留应用的 WebView 配置目录。不要只复制一个仍在写入的 SQLite 主文件。

原自动升级备份仅代表升级前的数据库，不包含之后新增记录，也不能代替个人笔记和对话备份。

## 回退路径

0.6.4 不认识新版本的全部字段，也不会按新版规则保护 schema 1。不能只换回旧 exe，再让它写升级后的库。

需要回退时：

1. 正常退出新版，完整保留升级后目录，换一个明确名称存档。
2. 在单独的恢复目录检查升级前备份可打开且完整，核对任务、事件和请求记录；保留一份原始备份。
3. 使用升级前数据库副本与对应旧版程序，恢复原先个人笔记/对话目录。不要把升级后库交给旧版覆盖。
4. 升级后新增的工作仍在第1步副本中；若要带回旧版，逐项整理或使用受支持的迁移操作。生成 Markdown 可辅助核对，不自动反向覆盖任务。

本轮合成测试验证了 WAL 一致性备份、重复打开不重复备份、备份失败不升级、未知版本拒绝，以及保存升级后新增数据后恢复到另一测试路径。证据见 [M1 数据验证](../../verification/p0p1/M1-data.md)。实际用户目录恢复未执行。
