# Inky 工作与学习数据方案

2026-09-06 需求更新：Agent 和 Inky 将共同读写同一份任务/计划，用户可在 Inky 手动修改。最新交互与数据归属见 [Agent 驱动的 Inky 使用方案](2026-09-06-agent-driven-inky-usage.md)。下文的单向导出仅适用于 Markdown 摘要，不限制 Agent 修改工作任务。

状态：设计提案，2026-09-05。用户当前尚无对应数据，将使用另一个独立 Obsidian 仓库。PKC 是个人知识库，不存放这里的日常计划与执行日志。本次未修改任何 Vault。

核心建议：围绕“想推进什么、实际做了什么、卡在哪里、接下来做什么”积累数据。先记足以影响明天安排的内容；Inky 自动记录执行事实，用户补充只有自己知道的结果和约束，Hermes 负责整理与建议。

## 五类数据

| 数据 | 最小内容 | 如何得到 | 能帮助 Hermes 做什么 |
|---|---|---|---|
| 目标与上下文 | 工作项目或学习主题、希望达到的结果、完成标准、可选截止日期 | 开始项目时用户填写；发生变化时再更新 | 判断任务是否有助于目标，解释优先级 |
| 今日安排与约束 | 今天可用多少分钟、固定占用、最多三件想推进的事、可选精力状态 | 每天启动时一句话；任务可从项目带入 | 给出实际能做完的计划，时间不足时建议缩减 |
| 执行记录 | 关联任务、开始/结束、实际专注分钟、暂停/放弃/完成、用户采纳的下一步 | Inky 自动记录；首版未实现，当前已有部分任务/专注字段可复用 | 继续上次任务，逐步校准估时，减少重复询问 |
| 结果与阻塞 | 产出链接或一句结果、尚未完成部分、卡点、下次从哪里开始 | 完成后或收工时补一句；允许跳过 | 生成复盘，识别需要先解决的阻塞，给出可开始的动作 |
| 学习反馈与稳定偏好 | 学习主题、可独立完成的练习、未理解的问题；常用专注时长、提醒偏好 | 学习时按需补充；偏好首次设置后按需修改 | 建议练习或复习；调整建议长度、时段和提醒方式 |

表中“自动记录”是拟议实现方式，并非已实现的新功能。计时结束和勾选任务是两种事实；不能把计时结束自动解释为完成产出。

## 第一周只需要这些

开始一天时回答两个问题：“今天想推进什么？”“大概能用多少时间？”目标不清楚也可以先写原话，由 Hermes 提一个可选下一步。

完成一段工作后，Inky 自动留下任务和用时；用户有产出时补一个链接或一句结果。中途切换时，可以只留“下次先做……”。

收工时，Hermes 根据真实记录生成草稿；用户只需修正漏项或写一个阻塞。未记录的时间保持未知，不补成工作时长。

第一周的数据足以检验“下一步建议是否有用”。第一天可以依据用户目标和当天约束给建议；估时和偏好学习要等有历史后再尝试，不能刚接入就声称了解用户的高效时段。

## 独立 Obsidian 仓库结构

```text
工作与学习/
  Daily/        每日计划、产出、阻塞、下次起点
  Projects/     工作项目的目标、完成标准、下一步
  Learning/     学习主题、能力目标、练习与疑问
  Inbox/        暂未归类的想法与输入
  Preferences.md  可选的长期约束与提醒偏好
```

不预建大量项目或标签；有真实内容再新增笔记。工作和学习都使用“目标 → 行动 → 结果”的结构，学习多一个“我是否能独立完成”的反馈。个人知识库保持独立，需要方法参考时再检索 PKC 并明确标注来源。

模板在项目的 `docs/templates/work-study-vault/`：

- [日记录](../templates/work-study-vault/日记录.md)：每日最常用的入口。
- [工作项目](../templates/work-study-vault/工作项目.md)：为长期工作提供目标和边界。
- [学习主题](../templates/work-study-vault/学习主题.md)：围绕可检验的能力安排练习。

这些是普通 Markdown 模板，不依赖 Obsidian 插件。空项允许保留空白；不要为了让模板完整而编造内容。

## 数据归属

| 类型 | 主记录在哪里 | 处理方式 |
|---|---|---|
| 目标、项目背景、用户写的结果与学习问题 | 独立 Obsidian 仓库 | 保留原始笔记，通过路径和段落引用 |
| 活动任务、计时状态、专注事件 | Inky SQLite | Inky 维护；日终导出摘要，不每秒写 Markdown |
| Hermes 建议 | Inky 建议记录，可导出到日记录的独立区域 | 标记为建议，包含依据、生成时间和采纳情况 |
| 导出的执行摘要 | 日记录中的 Inky 托管区域 | 稳定条目 ID 与输入版本；重复导出更新对应区域，保护用户正文 |
| 方法与概念 | PKC 个人知识库 | 按需参考；不是当日执行事实，也不是自动复盘目标 |

第一版采用“读取笔记 + Inky 内执行 + 单向导出”。Obsidian 中导出的勾选状态只是快照；若后来支持从两处编辑任务，再定义双向同步和冲突处理。用户在 Obsidian 新写的行动可以作为候选导入，采纳时建立来源关联和稳定 ID，避免重复任务。

## 建议的内部字段

以下由程序维护，不要求用户每天填写。字段名是提议，实际实现需与现有 TypeScript / Rust 数据模型共同确定。

| 对象 | 关键字段 | 作用 |
|---|---|---|
| SourceRef | `sourceId`、`vaultId`、`relativePath`、`heading`、`modifiedAt`、`contentHash` | 区分仓库、定位依据，发现来源变化 |
| Goal | `id`、`kind: work/learning`、`desiredOutcome`、`doneCriteria`、`dueAt?`、`sourceRef` | 用完成标准判断推进情况 |
| DayPlan | `localDate`、`timezone`、`availableMinutes?`、`fixedCommitments[]`、`taskIds[]` | 区分当天时间预算和已经承诺的安排 |
| Action | 现有任务字段，加 `goalId?`、`estimateMinutes?`、`nextStep?`、`sourceRef?` | 从项目定位到可以开始的一步 |
| Session / Outcome | 现有专注会话，加 `outcomeText?`、`artifactRefs[]`、`blocker?`、`resumeCue?` | 区分投入时间、实际产出与恢复线索 |
| LearningFeedback | `goalId`、`practice`、`result: independent/assisted/not_yet/unknown`、`openQuestion?` | 以实际练习调整下一次学习安排 |
| Suggestion | `requestId`、`inputRevision`、`generatedAt`、`sourceRefs[]`、`action`、`reason`、`decision` | 追溯建议；采纳、修改、跳过都可区分 |

没有的数据保持 `null` / `unknown`。自然语言截止日期保留原文；精确排期前再澄清。已有番茄完成数不能回填成历史产出，旧演示任务不能作为个人偏好的训练依据。

## AI 如何使用这些数据

| 触发 | 首先读取 | 输出 |
|---|---|---|
| “安排今天” | 当日时间预算、未完成行动、相关项目目标和截止日期 | 最多三项、估时、理由；安排时间不超过明确的可用时间 |
| “现在先做什么” | 当前目标、最近一次恢复线索、用户当前可用时间 | 一个动作和所需资料；理由引用来源或明确说明是推断 |
| “继续学习” | 学习能力目标、上次练习结果、尚未理解的问题 | 一个练习或复习建议；用练习反馈调整难度 |
| “今天做了什么” | 真实完成记录、专注会话、用户补充的产出 | 可编辑复盘，分别列出投入、成果和未完成内容 |
| “这个问题有什么方法” | 当前阻塞；必要时检索 PKC | 给与当前情境相关的方法，并区分工作事实与知识参考 |

按问题选数据，不把全部历史和全部知识库固定塞入每次请求。开始工作、结束工作可以有可选提示；专注中无需持续模型分析。

## 用一周试用判断数据是否值得继续记

优先观察四件事：能否更快开始、回来时是否知道接着做什么、复盘是否符合真实产出、维护记录是否太费力。建议采纳率不能单独代表效果，修改和跳过也可能是合理选择。

当某字段经常空着、又从未改变建议时，删掉或隐藏它。等已有稳定使用后，再考虑日历、应用级用时汇总、周期复盘；不预先要求收集屏幕、键盘内容或所有聊天。
