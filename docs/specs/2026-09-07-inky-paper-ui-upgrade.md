# Inky Paper UI 升级方案

日期：2026-09-07。定位：**Inky Paper 是一个住在纸上的 AI 工作助手。**

本轮交付为方案与现状检查记录，没有修改应用代码。检查对象为当前工作区，包括尚未提交的任务编辑、Agent 协作改动。浏览器 DEMO 用于检查页面与前端操作；桌面快捷键、真实 SQLite 保存、Agent 联通和模型调用未在本轮实测。

## 核心决定

用「一张工作便签 + 一条专注纸条 + 按需展开的纸页」组织 Inky。纸张负责组织信息，手绘角色负责少量陪伴，主要空间留给任务与结果。

**按本轮最新要求：新版不保留宠物升级系统。** 移除等级、XP、经验条、升级弹窗与奖励文案；也移除首页的连续打卡与重复统计。角色没有需要照料或解锁的成长目标，用户不用先命名才能开始工作。专注记录仍保留，用于找回真实工作过程。

视觉关键词：纸张感、手绘感、轻笔记感、温柔陪伴、低打扰、高可读性。采用现代、整齐的信息排版，手绘只出现在页边角色和少量反馈细节。

当前已经有任务编辑与 Agent 任务读写，不应继续按旧版本的功能缺口规划。Agent 接口当前只提供 list/get/create/update 四类任务工具，并不是通用 AI 作业与成果接收系统。

日期字段当前是文字信息，不能据此承诺自动排程、到点提醒或可靠的「今天任务」筛选。第一版页签继续叫「任务」。

## 2. 现状判断与优先改动

| 优先级 | 观察到的问题 | 影响 | 方案 |
|---|---|---|---|
| P0 | 首页宠物等级、心情、经验和底栏与任务争夺空间，底栏连续值为代码固定值 | 首屏层级分散，统计缺少可信依据 | 去除成长系统与连续打卡；把输入和当前行动提到前面 |
| P0 | 专注页有掌机外壳、双侧操作、英文标签及很小的文字 | 窗口虽小，任务与操作也被压缩 | 去掉外壳装饰；直接显示任务、时间、暂停；中文动作标签 |
| P0 | 任务输入超过 8 字后提交会进入 AI 解析流程，输入在解析期间禁用 | 普通记录的动作因文字长度改变 | Enter 始终直接记录；「AI 整理」成为可选操作，保留原始输入 |
| P1 | 编辑、拆解、历史和设置的容器与信息密度不一致 | 用户需要不断适应不同的小弹窗 | 统一为纸页：同样的标题、关闭、正文间距与底部动作区 |
| P1 | 产品新定位包含 AI 执行结果，当前没有对应结果数据与阅读入口 | 仅换配色无法支撑新的工作流 | 独立第二阶段接入结果，避免用任务同步状态冒充执行进度 |

这些是基于现有页面和代码的设计判断，尚不是用户研究结论。专注页代码中存在 5–8px 的辅助文字；具体设备上的可读性与点击误差需要在桌面版验证。

## 3. 页面结构

### A. 工作便签：常用主窗

建议从 **320×520 逻辑像素** 起稿，以 300×520 做紧凑适配检查。宽度只略微增加，优先通过删减信息获得留白，不扩大成常驻工作台。

从上到下为：

1. **轻页眉**：Inky Paper、一个 24–32px 手绘角色、更多菜单。明确一小段拖动区域。
2. **快速记录**：占一行的输入框。Enter 直接保存；「任务 / 随手记」由当前页签决定，不按输入字数决定是否请求 AI。
3. **当前任务**：有进行中或暂停任务时才出现，显示标题与「继续专注」；无活动任务时不放空卡片。
4. **任务 / 随手记**：两个文字页签。任务以规整清单行呈现；完成项折叠。第二阶段有结果能力后再加入「待处理」。
5. **轻状态反馈**：保存失败、冲突等需要处理的信息就近出现；普通成功短暂显示，不占一整条统计底栏。

任务行默认只展示勾选、标题、必要日期/优先级和开始按钮。普通优先级无需每条重复标注；番茄数、分类和完整步骤进入详情。删除放进更多菜单，提供撤销；悬停与键盘聚焦都能发现次要操作。

没有任务时显示「先记下一件要做的事」，焦点放在输入框；不先弹宠物命名。主窗不常驻心情选择，不重复展示专注总量。

### B. 专注纸条：工作时的小窗口

建议 **320×112**，需要记录念头时临时展开输入区。核心信息只有任务名、剩余时间、暂停和一个「随手记」入口。角色在边角保持静止，计时使用等宽数字。

暂停后保留剩余时间与任务；返回主窗时「继续专注」成为主要动作。退出本段的文案为「结束本次」，降低「放弃」带来的负面意味。结束时清楚区分「本轮专注结束」与「整个任务完成」。

完成反馈使用同一张纸条的展开状态，显示真实投入时长，以及「继续一段」「完成任务」「先休息」。不显示 GAME OVER、经验奖励、等级或庆祝动画。

保持原有 15/25/45 分钟能力，时长选择放在开工前或设置中；专注过程中不额外铺设控制栏。完成/暂停后的角色反馈最多一句，不遮住按钮。

### C. 详情纸页：需要阅读和编辑时展开

任务编辑、步骤整理、专注记录、设置共用一套纸页容器。短内容在主窗内展开，长内容才扩展窗口；未来 AI 长结果页建议约 **560×640**，关闭后回到原尺寸与位置，并限制在当前屏幕工作区内。

任务详情上半部是名称和步骤，下半部折叠分类、优先级、日期。AI 整理先显示可编辑草稿，用户明确保存后再应用；失败时保留输入，并能继续手动编辑。

编辑冲突继续保留草稿，但把「我的 / 最新」转换成有字段名的比较，例如「日期：我的 明天 → 最新 周五」。不要在面向用户的界面直接展示 JSON 或英文枚举。此项是现有冲突反馈的 UI 升级，不重写冲突算法。

设置分为「专注与窗口」「AI 与 Agent」「外观与陪伴」「数据与关于」。首页无需展示连接文件路径、数据库名称等实现细节；接入与排障时在设置中展开。

## 4. 视觉规范

### 配色

| 用途 | 颜色 | 使用规则 |
|---|---|---|
| 纸张 | 背景 #F2EFE7；纸面 #FAF8F2 | 纸面保持稳定、近乎不透明，保证复杂桌面壁纸上可读 |
| 铅笔文字 | 正文 #30332F；辅助 #686C63 | 正文与辅助文字都保留足够深度，避免「温柔」等于浅灰 |
| 辅助强调 | 鼠尾草底 #E7ECDD / 字 #52634F；灰蓝底 #E6EDF1 / 字 #4D6170 | 绿色用于主要行动与完成；灰蓝用于 AI 信息与来源 |
| 提醒与例外 | 柔黄底 #F5E7BE / 字 #7B5828；错误用低饱和陶土色 | 黄色表示需要看一眼，失败必须另有文字与重试动作 |

本轮计算的纯色文字对比度：正文/纸面约 12.06:1，辅助文字/纸面约 5.05:1，绿、蓝、黄标签约 5.22–5.45:1。实际纹理、透明度、禁用态和悬停态需在实现后重新测量。

### 字体、间距与材质

正文继续使用 Windows 可用的现代无衬线字体，如 Microsoft YaHei UI 与系统回退；任务标题建议 14–15px，辅助信息 12px，页标题 18–20px，计时 30–36px。手写字只用于品牌小字或一句角色旁白，没有合适且许可明确的字体时先用正文体。

以 4px 为间距基准，内容边距 16px，区域间距 16–20px；纸页圆角约 8–10px，弱阴影和细边界。控件与文字保持水平，不旋转任务卡或按钮。

纸张感来自暖色、留白和纸面层级。颗粒纹理仅在留白区域极轻地使用，不能压在正文上。正文区域不用横线本、做旧斑点、胶带或大面积渐变。手绘边缘留给少量装饰，交互区域保持清楚规则。

主要按钮建议高 36px，图标操作目标 28–32px；可交互轮廓不能仅依赖很浅的分隔线。普通文字以至少 4.5:1、必要控件边界以至少 3:1 为验收参考，依据 [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)。这些规范和目标尺寸不表示当前版本已通过无障碍认证。

### 角色与动效

保留 Inky 的辨识轮廓，重绘为炭黑铅笔线稿、少量单色点缀。首版只需要静静陪伴、专注、暂停休息、完成回应四种状态；AI 运行态必须由真实状态驱动，不靠角色动画暗示不存在的执行过程。

主窗角色 24–32px，空态可略大；迷你模式可显示一枚纸角角色或小书签。默认静止，仅在状态切换时做一次短动作。提供关闭旁白/动效的选项，并尊重减少动态效果偏好。

去掉所有等级、XP 和升级入口；不设计喂养、连胜、签到补偿或解锁外观。实施时现有任务与专注记录必须保留；旧 XP 字段可以先兼容读取但不展示、不再增长，不为改 UI 清空数据库。

## 5. AI 执行结果：第二阶段

当前内置 AI 返回任务或步骤草稿，外部 Agent 可以操作主任务。新定位里的「处理 AI 执行结果」需要新增结果协议、存储与界面，不能仅通过换皮实现。

建议每份结果关联任务，最少包含结果 ID、来源 Agent、收到时间、摘要、正文或产物链接、处理状态、可用下一步。执行状态与用户处理状态分开：AI 已返回结果，不等于用户已经验收；本地接口就绪，也不等于 Agent 正在运行。

| 状态 | 主窗的轻提示 | 纸页中的主要动作 |
|---|---|---|
| 已返回、待查看 | 待处理 1 | 查看内容与产物 |
| 需要用户信息 | 一行说明缺什么 | 补充信息；没有回传通道时明确显示当前可行入口 |
| 已查看、可继续 | 主窗提示收起 | 标记已处理 / 将下一步加入任务 |
| 失败或中断 | 关联任务下显示简短原因 | 保留上下文；支持时重试 |

只有在 Agent 提供可靠执行事件后，才显示「执行中」等状态。不得根据最近一次任务修改猜测进度，不展示假百分比。

普通结果静默进入「待处理」，不抢焦点、不展开窗口。完成后最多合并成一条提示。只有阻塞当前任务的明确问题才突出显示。

示例：Agent 返回「汇报提纲初稿」后，用户打开结果纸页，看到摘要、文件、未决问题和建议下一步；选择「加入任务」后生成行动，再进入专注。第一版不加入内嵌长聊天、项目看板、日历、Obsidian 同步或自动周报。

## 6. 实施顺序与验收

| 阶段 | 工作内容 | 完成判断 |
|---|---|---|
| 1. 三屏设计稿 | 工作便签、专注纸条、任务详情；结果纸页标注为未来能力 | 在真实小窗尺寸下，首先看见输入/任务/主动作；没有任何成长系统元素 |
| 2. 现有功能升级 | 统一颜色字体和纸页容器；去除成长 UI 与奖励；重排任务；显式 AI；简化设置与完成反馈 | 原有捕获、编辑、步骤、专注、暂停、历史可走通；记录和手动草稿保留 |
| 3. AI 结果闭环 | 结果协议、存储、待处理入口、结果页、后续任务操作 | 真实 Agent 结果能到达、打开、处理并继续行动；离线/失败可理解 |

实现阶段的验证重点：

1. 新用户无需命名、配置 AI 或选择心情，能在两分钟内记录真实任务并开始专注。
2. 长短输入都能立即本地记录；AI 失败不丢草稿，也不阻断手动操作。
3. 中文长标题、空列表、多步骤、保存失败、并发冲突都有清楚的布局和下一步。
4. 在 Windows 100%/125%/150% 缩放、多显示器和屏幕边缘检查字号、裁切、点击、拖动、展开后位置、托盘和 Alt+F；浏览器不替代这些检查。
5. Tab 可到达主要操作，焦点清楚，Esc 关闭当前纸页并返回触发位置；专注隐藏后继续正确计时，普通 AI 更新不抢窗口。

## 7. 本轮证据与限制

完整截图及逐步发现见 [现有页面检查记录](../assets/2026-09-07-inky-paper/inspection.html)。截图仅包含新开的浏览器 DEMO 和示例任务；没有操作真实桌面任务数据。

| 步骤 | 页面/操作 | 健康度与判断 |

| 01 | 首次命名 | 可跳过；仍挡住第一次记录，建议移出主流程 |
| 02 | 任务主页 | 主要入口完整；等级、标签、底栏造成密度偏高 |

| 08 | 查看历史 | 有时长与会话状态；保持事实记录，移出首页竞争 |
| 09–10 | 设置上下部 | 功能齐全；连接、宠物包和技术说明混在长列表 |
| 11 | 迷你模式 | 视觉占用小；原生拖动与托盘行为仍需桌面验证 |

AI 解析成功/失败页、计时自然结束、数据错误与真实同步冲突没有在本轮触发，相关建议仅基于代码核对。截图不能证明所有色彩、键盘和读屏器行为均合格。

实现定位：`src/components/FocusFlowWidget/FocusFlowWidget.tsx` 与同目录样式负责主体；`TaskEditCard.tsx`、`TaskBreakdownCard.tsx` 负责纸页编辑；`src/styles/global.css` 与 `src/App.module.css` 负责全局与预览；`PetRenderer` 负责角色；`src-tauri/src/main.rs` 与 `tauri.conf.json` 共同涉及窗口尺寸。新增结果能力还需类型、持久化与 Agent 桥接变更。

下一步：先画「工作便签、专注纸条、任务详情」三张同风格设计稿，按去掉成长系统后的信息量确认视觉密度。
