# Inky Paper 专注与生产力：基于现有 UI 的修改计划

日期：2026-09-09。交付类型：Product Design 流程检查与修改计划；未实施新功能。

依据：[已修订的执行教练方案](2026-09-09-interruption-recovery-coach-plan.md)。本文将其落实到当前 Paper 0.3.5 的页面、交互、功能依赖与验收顺序。

## 1. 设计结论

保留当前纸页、任务便签、铅笔进度、独立专注窗、透明宠物与足迹。围绕这些入口增加“本段工作”的上下文，并在开始、需要帮助、结束三个时机渐进展开教练能力。

用户目标始终是维持专注力和生产力。中断恢复是优先解决的困难；目标选择、持续投入、等待、解卡、休息和结果反馈共同构成完整体验。

最重要的三个修改：任务页从“开始一轮计时”扩展为“开始有目标的一段工作”；专注窗保持紧凑，帮助按需展开；足迹从逐轮计时记录扩展为按工作时段回顾目标与进展。

本次不创建新风格或三套视觉方案，不修改应用代码、正式数据库、Hermes 配置或可执行文件。新增界面的尺寸、文案和布局是下一步设计依据，尚未经过新 UI 的渲染验收。

## 2. 当前流程检查与证据

本次启动现有 debug 应用，加载当前本地页面，在独立测试数据中创建“理解文章中的核心概念”和“让登录流程跑通”两项示例任务。通过真实 Windows 窗口检查任务页、开始、安静态、暂停、结束、补充反馈、回执、足迹、设置首屏和迷你宠物。截图均为本轮新采集，保存后逐张检查。

没有读取原版 Inky 数据，也没有把旧设计截图当作当前运行证据。以下判断是现有体验与新增需求的差距，不代表已经验证教练有效。

### 1）任务入口：基础清晰，需要增加工作时段上下文

![当前任务页](../../output/product-design-20260909/screenshots/01-home.png)

已有优势：突出一个具体下一步，主任务作为上级信息，其他任务降为列表；主要操作清楚。现在的“进行任务”旁边是 15/25/45 分钟选择，它实际开始一轮计时，没有工作时段、预计结束时间或状态选择。

修改方向：复用当前绿色便签作为本段工作的中心，不另加一个平行的 AI 推荐卡。明确区分“这一轮计时多久”与“接下来工作到几点”。

可访问性风险：任务完成复选框和编辑图标较紧凑；新增点选控件不能进一步挤压。截图不能证明鼠标目标大小或对比度达标，实施时需实际测量。

### 2）专注执行：布局可复用，新增控制需要按需展开

![当前专注窗](../../output/product-design-20260909/screenshots/02-focus.png)

![当前安静态](../../output/product-design-20260909/screenshots/02-focus-quiet.png)

已有优势：320×164 的窗口中，任务标题、倒计时、铅笔进度对齐；底部只有暂停、宠物和随手记。安静态保留计时与进度，减少视觉干扰。

修改方向：保留中心轴和底部三组位置。工作时段、能量、AI 建议不加入常驻行；等待和卡点通过操作区展开。无计时的工作状态需要单独表达，不能伪装成运行中的计时器。

可访问性风险：安静态会隐藏操作。新菜单打开、输入中或键盘焦点位于操作区时应暂停自动淡出；新的状态不只用颜色表达。

### 3）暂停与恢复：已有线索入口，可扩展为暂停、等待、解卡

![当前暂停页](../../output/product-design-20260909/screenshots/03-paused.png)

已有优势：暂停后出现“回来先做什么？”及可选输入，用户可以继续或结束本轮。当前没有“等待 AI”和“卡住了”的独立语义。

修改方向：复用暂停时展开的空间，保留可选的一句话；增加明确等待状态和进入解卡帮助的入口。不能将每次暂停都算成走神，也不能把 AI 等待归为休息。

边界：本轮检查了输入框与可跳过路径，未完成文本输入保存的专项复测；不能据此宣称恢复文本的完整持久化已重新验收。

### 4）结束与反馈：完成语义清楚，文字反馈需要进一步减负

![当前一轮结束页](../../output/product-design-20260909/screenshots/04-round-end.png)

![当前展开后的反馈](../../output/product-design-20260909/screenshots/04b-feedback-expanded.png)

已有优势：“这一步完成了”“这一轮先到这里”“再专注一段”“先休息”分开；补充反馈可折叠。展开后有产出、卡点、下次起点三个文本框，窗口扩展到完整高度。

修改方向：每轮仍保持现有轻量结束路径；整段工作结束才展示一次进展点选。将自由文本留在“补一句”，选择卡住时再展开原因，不要求每轮填写能量与成果问卷。不能把“完成预期”的自评当作完成父任务。

可访问性风险：三个文本框及多种完成操作已占据大部分纵向空间。不能直接叠加另一套反馈；需要明确标题层级、分组和保存状态。

### 5）回顾与辅助入口：可沿用足迹和设置，宠物保持简洁

![当前足迹](../../output/product-design-20260909/screenshots/05-history.png)

已有优势：足迹已显示步骤、计时、暂停次数与结束状态，可显示已填写的成果和线索。当前以会话为单位，尚不能回答“这一小时想做什么、实际推进了什么”。

修改方向：在足迹内按工作时段分组，目标和进展在前，逐轮计时折叠在后。设置增加工作辅助的少量选项。迷你宠物不增加分数、徽章或持续通知气泡。

设置首屏与透明宠物的附加证据：[设置](../../output/product-design-20260909/screenshots/06-settings-top.png)、[宠物](../../output/product-design-20260909/screenshots/07-mini.png)。透明区域可透出桌面背景，这不是新增界面内容；设置截图只覆盖首屏，不能视作整页视觉检查。

### 检查边界

本轮检查的是现有 debug 桌面与当前页面，不是新功能实现或 release 回归。没有验证新的活动判断、后台 Hermes 调用、桌面提醒、多显示器定位或用户效果，也没有进行完整读屏、缩放和对比度测量。UI 自动化部分操作受控件支持限制，不能将工具输入失败判为应用缺陷。

## 3. 保留的视觉与操作规则

| 项目 | 当前依据 | 修改约束 |
| --- | --- | --- |
| 纸页与字体 | `paper.css` 后加载 `refinement.css`；最终字体为本地 Noto Sans SC，品牌使用现有手写字体 | 以最终级联样式为准，继续使用现有纸张、胶带、折角和图标资源 |
| 任务便签 | 单一当前步骤、弱化主任务、其他任务列表 | 复用便签承担工作目标，不新增推荐排行榜或第二套任务列表 |
| 窗口 | 主页面 320×520，专注 320×164，暂停 320×280，结束 320×320，随手记 320×322，宠物 160×160 | 新内容先用现有展开方式；尺寸不足时展开，不靠缩小文字硬塞 |
| 专注布局 | 居中标题、计时与铅笔，底部左右操作与中心宠物 | 新功能不改变计时/铅笔的透明前后位置；宠物保持当前角色 |
| 完成反馈 | 明确用户操作后保存与庆祝 | 保留步骤、任务和会话的区分；未知状态不填假数据，不新增等级/XP |

新主按钮建议沿用当前高度与样式。新选项的点击高度以至少 32px 为起点，主行动以至少 36px 为起点；这是桌面设计值，需在实际缩放下检查。标题优先保持 18–20px、正文 12–14px，不将关键说明压成小字号。长内容允许展开读取，关键操作不能被截断或只能悬浮查看。

## 4. 逐个界面的修改规格

### A. 任务页：把“本段工作”放进现有便签

未开启工作时段：保留当前下一步，主按钮改为“开始工作”，打开轻量开始页。将原 15/25/45 分钟选择移入开始页的“本轮计时”，避免用户把它当作整段工作长度。保留“只计时一轮”次要入口，允许使用已有简单功能。

工作进行中：便签显示“本段工作 · 到 17:00”、本段目标和当前下一步。主按钮按状态显示“回到这一轮”或“继续本段工作”，后者在无活动计时会话时打开工作状态页。提供一个弱化的“本段设置”入口，用于改结束时间、更新能量和结束工作。首页不同时显示两个大主按钮。

仅选中另一项任务不自动更换工作目标。明确选择“接下来做这件”才记录目标切换；存在运行会话时，先处理该会话，不能改写正在计时的步骤快照。

空任务页保留现有添加入口。用户可先输入一个任务名，再开始工作；不要求同时填难度、能量、估时与完成标准。

### B. 开始页：一个短流程，已有信息自动带入

采用当前 320×520 纸页式子页面，不叠加多层弹窗。返回时保留临时选择，任务列表暂不同时展示。

| 从上到下 | 内容 | 交互 |
| --- | --- | --- |
| 本段目标 | 当前任务、下一步或已有完成标准 | 默认只读，点“调整”再编辑 |
| 预计结束 | 建议默认从现在起 60 分钟，显示实际结束时刻 | 快选 30/60/90 分钟并可改具体时间；默认值是建议，不视作已确认个人习惯 |
| 现在状态 | 充足／一般／偏低 | 可选，未选为未知；不沿用上一段能量 |
| 本轮计时 | 15/25/45 分钟／暂不计时 | 默认沿用计时偏好，与工作结束时间分开 |
| 开始 | “开始工作并计时”或“开始工作” | 文案随计时选择变化，明确操作效果 |

开始按钮只在目标和结束时间有效时可用。已有清楚下一步不补问完成标准；缺失时再提供一句短输入。困难程度先由 Hermes 从任务上下文估计，用户需要时修正，不增加必填题。

建议交互预算：已有任务可零文字开始；使用默认时间且跳过状态时，点击首页开始和确认共两次。选择能量增加一次点选。这个预算是设计验收目标，尚未实测新界面。

### C. 专注窗：保留 164px，展开帮助而不堆按钮

默认保持现在的标题、倒计时、铅笔和底部布局。左侧“暂停”保留直达；旁边增加小型“更多工作操作”入口，与暂停组成同一组。中间宠物和右侧随手记不改变作用。

更多操作展开时将窗口临时扩展到暂停页级别，列表提供“等待 AI”“卡住了”“本段工作”。打开菜单时暂停安静态淡出，关闭后回到原布局与焦点。不能在 164px 窗口内硬挤下拉内容而被裁切。

这项设计存在可发现性与常驻空间的取舍：首个原型需验证用户能否找到等待/卡住入口；若图标入口难找，应调整有文字的入口，而不是继续缩小图标。新入口有可访问名称和键盘操作，不能仅靠长按或右键。

选择“暂不计时”的工作状态使用同样纸页语言，显示当前下一步、预计结束时刻与等待/帮助入口，不显示假的倒计时或已专注分钟。

### D. 暂停、等待 AI 与卡住：共享展开空间，保留不同含义

| 状态 | 用户看到什么 | 操作与计时关系 |
| --- | --- | --- |
| 暂停 | 已停下的计时、原步骤、可选“回来先做什么” | “继续”显式恢复当前计时；原“结束本轮”保留 |
| 等待 AI | “等待 AI”、原任务、可选“回来先检查什么” | 若有运行计时，选择等待就是一次明确暂停动作并记录原因；“回来继续”显式退出等待并恢复，或只回到无计时工作 |
| 卡住了 | “哪里不顺？”及少量原因选项 | 可选“下一步不清楚／遇到问题／状态下降”，再展示帮助；打开面板不自动停钟，保留暂停入口 |

AI 等待不能由窗口切换自动进入，系统最多请求确认。没有完成信号时显示“等待结果”，不能声称结果已经生成。工作结束时间仍独立生效。

卡点帮助优先围绕原目标给一个建议，如“先复现一次失败并记录错误码”。只展示一句理由和“采用／调整／暂不”入口；长讨论放在 Hermes。Hermes 未连通时显示已有线索和手动编辑入口，不假装生成了建议。

### E. 桌面提醒：独立轻提示，避免顶开原工作

建议新增宽 320px、高约 180–220px 的临时提示窗，使用现有纸页资源与文字样式。它与主窗口、宠物窗分离，不把当前专注窗强制切换成聊天页，不抢输入焦点。靠近当前屏幕的 Paper/宠物停靠位置，屏幕边缘自动避让；隐藏或托盘时仍能显示一次轻提示。

内容顺序：短提示“要接着刚才这一步吗？”、当前下一步、最多两行的恢复线索。主操作“回到任务”；次操作“5 分钟后”“我在正常工作”。“回到任务”沿用先前确认的“继续”行为，仅打开任务和线索，避免被误解为自动启动计时。

首次无回应或选择稍后，5 分钟后最多再提示一次；之后关闭本次追问。“我在正常工作”抑制本工作时段相同上下文。休息、等待、工作结束取消待发提示。请求或系统状态记录成功后才显示已处理。

持续阅读或在 AI、浏览器、终端之间正常切换不直接弹提示。不了解上下文时保留未知，不为了让功能“显得主动”制造提醒。

### F. 一轮结束与工作结束：拆开问题，减少重复填写

一轮结束继续使用当前 320×320 布局，保留步骤完成和结束本轮两个明确操作，以及再专注/休息。当前三项文字补充保持折叠，不叠加一套必填能量和进展选择。工作时段内增加一句轻量说明“本段工作仍在继续”，实际空间需原型验证。

工作时段结束使用单独的 320×520 纸页：显示开始时目标，进展提供“完成预期／推进了一些／卡住了”；可跳过。选择卡住才展开原因。补一句只在需要时展开，优先带入已填写内容。

投入程度点选只在部分工作时段抽样出现，允许跳过；能量只在用户主动更新时再次填写。保留底部固定保存入口，表单内容单独滚动，避免展开后找不到结束操作。

到点的轻提示提供“延长 15 分钟”“结束本段”；改其他时间放到本段设置。无回应时停止本段监督、不自动延长。若仍有运行中的计时，结束页明确提供“结束工作并结束本轮”或“结束工作，保留计时”操作；不能悄悄结束计时或把计划到点当作任务完成。

保存后沿用现有回执风格。对只结束一轮的操作可以保留现有回执；不要再连着弹工作结束回执和重复问卷。

### G. 足迹与设置：在原入口上增量展示

足迹按工作时段组织：先显示目标、时间范围和自报进展，再展示可选成果/下次起点；展开后看多轮专注、休息和等待。没有工作时段关联的旧记录保留原有列表形式，不造出历史目标和能量。

不显示“今日专注力 87 分”等自动推算。计时、行为分类、自报投入、产出分别标明。只在确有反馈时展示“本段有 1 次提醒被标为正常工作”，不把未回应算作接受。

设置在“与 Hermes 协作”附近增加折叠的“工作辅助”组，集中放活动采集说明、提醒开关与保留策略。默认只有工作时段内观察。工作开始前用一次简短说明明确会读取应用名、窗口标题和停留时间，不每轮重复。

保留现有文案对“本地同步服务可用”和“Hermes 已连通”的区分。实时活动摘要留在按需查看的详情中，不占用任务页，也不为了设置新功能新增仪表盘。

## 5. 数据与功能对应关系

| 界面改动 | 可复用能力 | 必须增加或调整 |
| --- | --- | --- |
| 开始与本段工作 | 任务、步骤、版本、计时入口 | 工作时段、目标快照、结束时间、点选状态、与会话的关联 |
| 暂停/等待/帮助 | 暂停/恢复、恢复线索、随手记 | 工作模式、等待原因、卡点选项；避免与计时状态混为一个字段 |
| 桌面轻提示 | 现有桌面窗口与系统无输入接口 | 前台应用/标题采样、候选判断、独立提示窗、展示与响应记录、重试去重 |
| Hermes 建议 | 六个 MCP 工具、历史与事件、版本校验 | 工作上下文读取、受限提案、主动调用链验证、提案有效期与接受记录 |
| 工作结束与足迹 | 结束事务、历史、反馈和回执 | 进展点选、抽样投入反馈、工作时段分组、旧记录兼容 |

数据实体沿用总方案中的 `WorkBlock`、`StateCheckIn`、`ActivitySegment`、`InterruptionEpisode`、`PromptEvent`、`ProgressFeedback`、`FocusFeedback` 与 `CoachProposal`。UI 展示事实和建议的来源；从标题推断的相关性不自动成为用户确认。

Paper 必须能在 Hermes 离线时完成开始、采样、有限提醒、手动恢复和结束。模型不参与逐秒监控，现有 `read_events` 不会自动唤醒它。端到端主动调用仍是待验证依赖，不能先在 UI 写“AI 正在监督”来掩盖缺失的后台能力。

新增操作仍使用命名事务与幂等 ID。开启工作并开始计时应具有明确的成功/失败语义，不能界面显示已开始而数据库只保存一半。历史步骤快照、用户手动修改和原版隔离边界保持不变。

## 6. 实施批次与优先级

| 批次 | 范围 | 依赖与完成条件 |
| --- | --- | --- |
| P0.1 语义与状态 | 区分工作时段、计时轮次、等待、休息、任务与步骤；建立数据迁移 | 新旧数据往返、异常恢复、明确完成语义通过 |
| P0.2 开始与结束 | 任务便签、开始页、状态点选、整段结束、足迹分组 | 已有任务零文字开始；可跳过；多轮归属正确；到点不自动延长 |
| P0.3 等待与帮助入口 | 专注操作区、展开面板、等待 AI、卡点入口 | 保持 164px 主态；菜单/输入时不消失；等待不会被当作偏离 |
| P1 本地专注支持 | 活动信号、相关性规则、桌面提示、5 分钟一次重试、误报纠正 | 托盘/迷你可见、不抢焦点；阅读不因无输入被提醒；重启不重复催促 |
| P2 生产力教练 | Hermes 上下文/提案、开始匹配、解卡与节奏建议、结果回读 | 真正打通调用链；用户能采用或修改建议；能观察目标推进与专注体验 |

P1 可用于日常试用专注支持，但“会提醒”不代表实现了全部目标。P2 才覆盖完整的专注与生产力教练闭环，仍需用户使用反馈验证价值。

实现落点建议：`PaperApp.tsx` 保持页面编排，新增工作时段/教练逻辑拆成小组件与 hooks，避免继续把所有状态塞入根组件；`paper.rs` 增加兼容数据与事务；`main.rs` 接入本地采样和提示窗；桥接与 MCP 扩展明确命名能力。新增样式集中管理，并核对 `refinement.css` 的覆盖关系，不在两个文件末尾反复叠加冲突规则。具体模块名由实现时确定。

## 7. 关键状态和设计验收

| 场景 | 必须观察到的结果 |
| --- | --- |
| 阅读资料，长时间不操作 | 不自动判分心；开始前状态可点选，结束后可记录理解了什么 |
| AI 开发，跨应用查资料和测试 | 不凭切换次数判断偏离；目标和当前步骤保持可见且版本正确 |
| 明确等待 AI | 工作时段继续，当前计时按用户等待操作暂停；没有生成完成信号就不宣称已完成 |
| 突然中断且没留话 | 展示已有步骤与目标，不编造进度；提示可延后且不会无限追问 |
| 卡住但仍停留在同一窗口 | 不自动推断卡住；用户可快速进入帮助，得到一个可执行的调整 |
| 计时到点，但工作时段没到点 | 只进入本轮结束处理；可继续下一轮，工作时段不丢失 |
| 工作时段到点但计时仍运行 | 停止监督并询问延长；计时的结束或保留由明确操作决定 |
| 反馈和采集缺失 | 显示未知或未填写；不生成能量、成果或专注分数 |
| Hermes 离线/提案过期 | 本地流程可用；没有已保存的虚假提示，过期建议不覆盖新步骤 |
| 高缩放、长标题、键盘操作 | 关键文案可读，菜单不裁切，操作区有焦点，不因自动淡出丢失可操作性 |

新 UI 原型优先检查三个高风险衔接：开始页中的两种时长；164px 专注窗如何进入等待/卡点；结束一轮与结束整段工作。其余视觉细节在这三个衔接成立后迭代。

真实桌面验收继续使用独立测试数据。检查每个新页面的正常、空值、保存中、失败、重开、长文本和高缩放状态；不以单张截图宣称完整可访问性合规。未来代码交付执行项目要求的测试与 release 可执行文件同步，本轮不运行无关构建。

## 8. 如何验收产品价值

主要结果：可选主观投入是否改善，开始时想推进的事情是否得到有价值的进展。过程证据包括恢复是否更容易、卡点建议是否有帮助；打扰、误报、输入次数作为约束。

正常使用输入预算：开始最多一个状态点选；执行中零必填；等待一次快捷操作；结束进展一次点选并确认，可跳过；文字仅用于新目标或用户想补充的时候。抽样投入问题不能变成每轮固定问卷。

学习与开发分开回顾，也考虑能量、任务大小和反馈覆盖率。计时分钟数、电脑活跃时长、任务数量不能单独证明生产力提升。不预设改善百分比，也不承诺仅凭窗口标题获得真实专注度。
