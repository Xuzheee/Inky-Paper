# Inky Paper：专注与生产力执行教练方案

日期：2026-09-09。状态：方向已在讨论中确认；本文为具体改进方案，尚未实施。用户进一步明确：主要任务是帮助维持专注力和生产力；中断恢复是实现这一目标的重要能力。

## 1. 结论与目标

现有 Paper 足以作为执行教练的数据与界面底座，但尚不具备完整的电脑活动感知、工作时段管理和主动教练闭环。产品主要任务是帮助用户在自己设定的工作时段内维持专注，并持续推进有价值的学习与工作。中断后忘记回来、丢失继续线索，是已确认的高频问题和首要切入口，不能代替整个产品目标。

工作闭环覆盖：开始时选定适合当前状态的具体目标；执行顺畅时保持安静；偏离时帮助回来；卡住时调整行动；疲惫时支持休息；结束时确认实际进展。能量、任务难度、可用时间和历史贯穿目标选择、步骤大小、节奏与恢复建议，不只用于中断后的补救。不承诺自动找到个人的“最优任务”或直接测量真实注意力。

典型场景是阅读资料学习，以及使用 AI 开发应用。两者均可能长时间无输入，并需要跨应用切换；电脑活动只能说明观察到的行为，不能直接证明分心、学习效果或产出。

产品承诺：用户明确开启工作时段，简单选择状态；Paper 帮助维持当前目标、记录执行事实并提供适量提示；Hermes 协助选定可推进的下一步、处理卡点和调整节奏，并利用少量反馈改进建议。成功表现为用户更容易持续投入并获得有价值的进展，而非提醒次数增加、电脑操作增多或计时更长。

| 目标 | 产品应帮助什么 | 判断依据 |
| --- | --- | --- |
| 维持专注 | 围绕当前目标持续投入，减少不想发生的偏离，需要时能回来 | 可选主观专注反馈、确认过的偏离和恢复；活动信号仅为辅助证据 |
| 维持生产力 | 在可用时间与状态下推进明确目标，卡住时找到可执行的调整 | 本轮目标、结束进展、已有产出或用户确认；不按简单任务数量计分 |
| 维持可持续节奏 | 合理安排等待和休息，状态不佳时缩小动作或调整计划 | 用户状态与选择、后续进展；不默认把休息视作损失 |

本轮只新增本方案，不修改代码、可执行文件、数据库或 Hermes 配置。原版 Inky 的数据和连接不在范围内。

## 2. 已确认的产品选择

| 项目 | 已确认方向 |
| --- | --- |
| 主要任务 | 帮助用户在工作时段内维持专注力和生产力 |
| 已确认的主要困难 | 中断后忘了回来，有时不知道从哪里继续；作为优先切入口 |
| 工作时段 | 用户明确开启并给出预计结束时间；包含多轮专注、等待和休息；到点询问是否延长 |
| 活动信号 | 应用名称、当前窗口标题、停留时间，结合电脑无输入时长 |
| 状态输入 | 开始或结束时点选；尽量减少文字输入，不重复询问已有信息 |
| 恢复线索 | 暂停时可选补一句，不强制填写 |
| 等待 AI | 可快捷标记；系统可以提出确认，不能仅凭切换就判定进入等待 |
| 提醒位置 | Paper 轻量桌面提示；需要讨论卡点时再进入 Hermes |
| 追问 | 首次提醒后，点击稍后或无回应，5 分钟后最多再问一次；仍无回应停止本次追问 |
| 纠正误判 | 点击“我在正常工作”撤销本次判断，避免同一情况连续触发 |
| 控制权 | 返回任务不自动开始计时；任务完成、步骤完成与结束一轮保持分离 |

以下阈值、保留期限、接口命名和实现顺序属于建议实现值，并非用户逐项确认或效果已验证的事实。

| 能力 | 当前事实 | 本次增量 |
| --- | --- | --- |
| 任务与步骤 | 分类、优先级、自由文本截止时间、单一当前下一步、版本和来源 | 复用；需要时补本轮完成标准与可纠正的估时 |
| 专注与休息 | 会话、步骤快照、暂停恢复、结束和历史 | 新增外层工作时段，关联多轮会话；不替换现有计时器 |

| 页面安静模式 | `useFocusQuiet.ts` 只根据 Paper 内部交互淡出控件 | 保持现有视觉功能；它不是整机专注检测 |
| 应用切换 | 当前 Paper 未发现前台应用/标题采集 | 新增本地前台应用、标题与活动区间采集 |
| Hermes | 六个 Paper MCP 工具，能读任务、历史、事件，创建和更新任务 | 增加有限教练上下文与提案能力；主动调用链需单独验证 |
| 提醒学习 | 未发现推荐曝光、响应、恢复或误报记录 | 增加一次中断判断到用户响应的关联记录 |

`read_events` 是拉取接口，不会主动唤醒 Hermes。现有 MCP 服务的可用性也依赖 Paper 运行。不能把“有事件接口”当作“已有后台教练”。

## 4. 用户流程

### 开始工作

从已有任务进入，自动带入当前下一步。选择预计结束时间，状态提供“充足／一般／偏低”，可跳过。状态没有选择时记为未知，不默认一般，也不沿用过期记录。

已有下一步足够具体时直接开始工作时段。只有缺少目标时补问一句，如“这段时间想推进到哪里？”支持自然语言建立工作时段，但不要求每次说完整句子。开启工作时段与开始专注计时是不同操作；可在同一界面提供明确的“开始工作并计时”按钮。

开始时复用已有任务与完成标准。若用户请求建议，Hermes 可结合能量、可用时间、任务重要性与历史提出一个适合本段的动作；已有目标明显过大时可建议缩小。例如“状态偏低，先复现登录失败并记下报错”，而不是机械推荐另一件容易完成的小事。建议由用户接受或修改，不自动更换用户选定的目标。

### 执行中

在现有任务页或专注页用简洁文字显示本段工作及结束时间，不增加常驻分析面板。暂停、休息、等待 AI 均有快捷入口。恢复提示优先取用户留下的话，其次取已有步骤和相关笔记；没有具体线索时只展示原目标，不声称知道用户阅读到哪一段或代码改到了哪里。

维持专注也包括减少教练本身造成的打断：已有相关活动且没有其他依据时保持安静。提供可随时点开的“卡住了”入口，并在用户主动结束一轮、反馈卡点或更新状态时提供步骤调整机会，不新增固定频率的进度问卷。仅在一个工作窗口停留很久不能证明推进，也不能证明卡住。

建议先围绕同一个目标调整动作：学习时可以从继续收集资料改为用自己的话解释一个概念；开发时可以从继续要求 AI 重写改为复现问题、验证一个修改。是否采用取决于实际目标和卡点，不把固定方法强加给每个任务。状态偏低时可以缩小动作或建议明确休息；休息是工作节奏的一部分。

“等待 AI”由用户明确标记，或在系统提议后确认。等待期间停止疑似偏离追问。用户返回相关窗口时可以显示“查看刚才的结果”入口；窗口标题和停留时间不能可靠证明生成结束。更精确的完成通知属于后续按具体 AI 工具验证的能力。

### 提醒与回来

提示内容控制在原任务、恢复线索和“继续／稍后／我在正常工作”三个动作内。没有抢占键盘焦点的弹窗；提示出现不打断输入。Paper 在托盘或迷你态时仍需要能够展示提示，这属于新增桌面能力，不能只在隐藏的主界面里写一条消息。

“继续”打开任务及恢复线索，不自动计时，不等同于确认恢复成功。“稍后”和无回应执行已确认的 5 分钟规则。“我在正常工作”撤销判断，在当前任务与相关活动上下文中抑制重复提示，不把整个应用永久加入免检名单。

用户明确休息或进入等待 AI 后，取消待发追问。一个中断事件最多显示两次提示，不能换一个事件 ID 对同一情况继续催促。

### 结束或延长

到预计结束时间，停止新的偏离判断和追问，询问是否延长；无回应不自动延长。现有运行中的计时会话仍遵守用户明确控制规则，不能由教练擅自结束。

结束反馈提供“完成预期／推进了一些／卡住了”，可跳过。选择卡住后才展开原因选项，例如“下一步不清楚／技术问题／被打断／太累了”，另保留文字入口。进展反馈不自动勾选步骤或父任务。能量只在用户需要更新时再选择，不要求结束时重复填写。

为判断是否帮到了专注，可在部分工作时段结束时提供一个可跳过的点选：“投入程度：比较投入／时断时续／很难投入”。这是建议新增的抽样反馈，不要求每轮填写；与进展、能量分别存储，不能用其中一个推导另外两个。成果优先引用已有记录：学习可以是解释清楚的概念或解决的问题，开发可以是验证通过的功能或定位的错误，不要求上传文件作为证明。

## 5. 检测与提醒规则

第一版采用可解释规则与用户反馈，先不训练个性化模型。任务相关、可能无关、未知三类判断必须分开。单纯切换频繁、停留很久或无输入均不能独立判为分心。

| 情况 | 建议处理 |
| --- | --- |
| 在资料窗口持续阅读，无键鼠输入 | 保持未知或相关阅读，不因此弹提醒 |
| 文档、浏览器、AI、终端之间切换 | 结合本轮目标和已确认的相关上下文；切换本身不触发 |
| 曾被用户确认无关的上下文持续停留 | 达到持续阈值后形成候选；不把“浏览器”整体认作无关 |
| 长时间无输入后重新操作 | 作为重新检查的机会；若仍处于相关任务，不仅因刚才空闲而提醒 |
| 明确暂停后回到电脑，原步骤未恢复 | 可出现带恢复线索的提示，受统一提醒次数约束 |
| 休息、等待 AI、工作时段结束 | 不发送偏离提醒 |
| 只知道应用名、窗口标题缺失或任务关系不明 | 保留未知；不编造分类或自动当作分心 |

供试用的初始参数：前台信息约每 5 秒采样并在本地合并连续区间；无输入达到 3 分钟进入空闲候选；返回后留 60 秒观察窗口；较明确的无关上下文持续 3 分钟才产生首次提示候选。这些数值是可调起点，不是研究得出的个人最优阈值。

全局再加每 30 分钟最多两条中断提醒的建议上限，首次和追问都计入；工作结束通知单独处理。点击正常工作后，对该任务下相同上下文在本工作时段内抑制同类提示，用户主动撤销或切换目标后可重置。检测到持续返回相关上下文至少 2 分钟可关闭本次事件，但只标为行为代理证据，不标为已验证的专注。

重启、设备睡眠和采样失败形成明确缺口；恢复后不补算缺口活动、不补发成串通知。超过预计结束时间不恢复监督。提醒次数、已回应状态与追问截止时间持久化，防止重启清零后重复催促。

## 6. 最小数据设计

使用稳定 ID 把工作时段、当时任务、活动摘要、提醒与反馈关联起来。以下为拟定对象，新增字段或表需向后兼容。

| 对象 | 最少信息与含义 |
| --- | --- |
| `WorkBlock` | ID、开始/预计结束/实际结束、生命周期、任务/步骤引用、目标与完成标准快照、版本；任务切换另记事件 |
| `WorkMode` 事件 | working / paused / rest / waiting_ai 及起止时间、来源；与 focus/rest 会话状态分开 |
| `StateCheckIn` | 工作时段、时间、可选能量档位、来源；仅在本段有效，可更新 |
| `ActivitySegment` | 起止、应用名、窗口标题、观察到的无输入时长、数据质量；连续相同上下文合并 |
| `InterruptionEpisode` | 工作时段/任务版本、触发依据、相关性及来源、当前状态、提醒次数、下次可提醒时间 |
| `PromptEvent` | 计划、实际展示、响应或未响应、关联中断 ID、内容/规则版本；发送成功不等于用户看见 |
| `ProgressFeedback` | 工作时段、可选进展档位、卡点类别、现有文本反馈引用；缺失仍为未知 |
| `FocusFeedback` | 工作时段、可选主观投入档位、反馈时间与来源；不等于能量、活动分类或产出 |
| `CoachProposal` | 类型（目标建议/步骤调整/恢复/节奏）、上下文时间、任务/步骤版本、建议动作、依据、接受/修改/拒绝结果；不能直接改写执行快照 |

任务估时与认知负担先作为 Hermes 可提出、用户可修正的辅助元数据，不要求用户创建任务时填表。记录 estimated / user_confirmed 来源，避免把猜测当事实。预估时长与计时器计划时长分开；优先级不能替代难度。

建议活动原始窗口标题只在本机短期保留 24 小时，超过后删除；去除原始标题的活动分类、提醒及反馈摘要先保留 30 天用于试用复盘。任务、既有会话和用户笔记沿用原有保存规则，不被这项清理影响。这是待实施的保留策略建议，尚未配置。默认不在工作时段外采样。

## 7. Paper 与 Hermes 的分工

Paper 负责工作时段、采样、规则、轻量提示、重试上限和事实记录。即使 Hermes 离线，用户仍能开始、暂停、查看已有线索和结束工作。

Hermes 负责开始时的目标与状态匹配、执行中的卡点与步骤调整、恢复和节奏建议，以及结束后的进展复盘。先沿用现有六个工具；如需新增，建议限定为 `inky_paper_get_coach_context` 和 `inky_paper_propose_coaching_action` 两类命名操作。前者只读，后者保存有版本和有效期的提案，类型限定为目标建议、步骤调整、恢复或节奏。接口名称尚未实现。

开始工作对话可由 Hermes 整理成待确认内容；真正开启工作时段和计时仍在 Paper 明确确认。自动采样不能每 5 秒调用模型。只有需要语义理解的候选或用户请求帮助时，才考虑向 Hermes 提交经过本地整理的必要上下文。

后台触发 Hermes、取得响应、返回 Paper 的实际机制必须先做技术验证；当前 MCP 本身不完成这条链。验证项包括已安装 Hermes 是否有可用的非交互调用入口、超时处理、重复请求、模型不可用和响应过期。若该链未打通，先交付本地恢复提醒和用户主动打开 Hermes 的帮助流程，不宣称已经具备主动 AI 判断。

窗口标题与历史笔记作为不可信数据传入模型，不能作为工具指令执行。模型结果只能是受限提案；保留 Bearer、本机桥接、字段白名单、版本冲突与幂等校验。扩展命名操作需要同时更新桥接、MCP 描述及项目数据约定，不新增全量快照覆盖入口。

提案和恢复提示绑定任务/步骤版本。用户或 Hermes 改了下一步，旧提案不得盖上去；过去的计时快照与历史保留不变。

## 8. 实施顺序与交付边界

### P0：工作时段与低输入成本

复用当前任务、计时和恢复线索。新增工作时段、预计结束、目标与完成标准、能量点选、结束进展点选、等待 AI；关联既有会话。先让用户能完整走一遍开始—执行/暂停/等待—继续—结束，并获得最小的进展基线。

验收：正常开始不要求重新输入已有任务；状态可跳过；工作时段包含多轮计时；到点无回应不延长；结束进展不误勾任务；旧数据库兼容，重启保留正确状态。

### P1：本地感知与有限提醒

接入系统无输入、前台应用、窗口标题和停留区间；实现可解释候选、Paper 桌面提示、5 分钟追问、次数上限与误判纠正。记录真实展示和响应。

验收：阅读无输入不被直接判断分心；正常跨应用工作不因切换次数被提醒；明确偏离可触发候选；同一事件最多两次；休息/等待/结束撤销追问；托盘和迷你态实际可见且不抢焦点；休眠重启不会追发通知。

### P2：Hermes 专注与生产力教练闭环

完成调用链验证、限定上下文和提案契约。覆盖开始时匹配目标、卡住时调整步骤、偏离后恢复和状态变化时调整节奏。能量、任务负担、可用时间与历史用于给出有依据的单个建议；例如把一个复杂修改缩小为可验证的小步骤。记录建议是否被接受、修改和执行，以及本轮最终进展，不自动重排所有任务。

验收：真实 Hermes 能读到关联上下文并返回可用提案；离线不阻断本地流程；旧提案失效；未调用成功不显示已保存；真实用户能在学习和 AI 开发两类场景中选定目标、维持执行、处理中断或卡点，并报告实际进展。技术验收通过不代表已证明专注或生产力提升。

P1 是可以日用的专注支持基础版本，覆盖活动感知和中断提醒，但不能作为完整产品目标已经达成的依据。P2 是首个覆盖专注与生产力教练闭环的交付点，效果仍需真实使用检验。个人节律预测、广泛推荐排序、截图/OCR、网站内容读取、跨设备监测和 AI 生成完成检测均不纳入这三个阶段的必要范围。

## 9. 如何判断有用户价值

以维持专注和推进有价值目标为主要结果，中断恢复作为解释效果的过程指标。先收集基线，再小范围启用提醒和教练建议。建议先用 3–5 个工作日观察记录与主动恢复入口，再用约 5 个工作日开启有限提醒；P2 上线后另行观察步骤调整等建议。比较时区分学习与开发、任务大小、时段与已报告能量，同时报告反馈覆盖率。这是形成改进线索的试用安排，不足以证明因果效果，不能把遗漏反馈当作差或好。

| 指标 | 定义与边界 |
| --- | --- |
| 专注体验（主要结果） | 可选主观投入档位与用户确认的偏离情况；报告有效反馈数量，不生成伪精确的注意力分数 |
| 有价值的进展（主要结果） | 对照开始时的目标与完成标准，记录结束进展及可选产出；区分学习和开发，不按任务数量或计时排名 |
| 恢复与解卡（过程指标） | 点击继续、明确恢复、返回相关上下文的时延，以及步骤调整是否有帮助；行为代理与用户反馈分开，不直接等于产出 |
| 误报与输入负担（约束指标） | 正常工作响应占已回应提示的比例、延后、关闭、未回应率，以及每段输入次数；未回应不算接受 |
| 节奏是否可持续（约束指标） | 可选状态更新与休息/等待选择，观察为了完成目标是否反复延长；不以取消休息或工作更久定义成功 |

初始技术通过标准以闭环成立为先：用户能定义目标、得到适用的步骤建议，在需要时恢复或解卡，并记录实际进展；输入可跳过，提醒次数严格受控，不篡改执行事实。产品价值成立需要真实使用中专注体验或目标推进改善的证据，并检查另一项是否恶化以及打扰负担是否可接受。仅仅更快回来、点击提醒更多或计时更长都不够，暂不虚设提升百分比。

## 10. 实施时的验证要求

本轮为文档交付，不运行与改动无关的构建测试。实施时针对新增状态转换、重复提交、工作结束、提醒计数与过期提案进行必要测试；不为界面文字变化增加复述实现的测试。

按项目要求执行 `corepack pnpm typecheck`、`cargo test --manifest-path src-tauri/Cargo.toml` 和对应构建。真实桌面在独立 `INKY_PAPER_TEST_DATA_DIR` 下验收，使用测试窗口标题和任务，不读取原版 Inky 数据。正式版忽略该调试变量。

桌面验收必须覆盖真实阅读、跨应用切换、等待 AI、暂停恢复、无响应追问、托盘/迷你提示、工作结束和重启。完成代码交付后才构建 release，同步到 `app/Inky Paper.exe` 并验证实际可执行文件。本次不执行此同步。
