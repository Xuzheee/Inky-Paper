# 0.6.0 工作台验收

本轮使用真实 Tauri / WebView2 与已安装 Hermes ACP。Paper 测试库为 `output/workbench-acceptance-2/paper-test`，通过 debug 专用变量与独立应用标识启动；正式数据未用于测试。真实模型会在 Hermes 中留下对应验收对话。

## 通过项

类型检查、前端 104 项、Rust 67 项通过；1 项历史负载基准未运行。release 构建通过，交付文件 SHA-256 与构建产物一致。

- UI 新建任务 / 步骤 / 时间安排；与 Paper 原窗口读取到同一任务。
- 手动完成和撤销只改变步骤，父任务未完成，也没有生成计时。
- 跨日拖动保存到正确日期；日程展示保存的时间；选择下一步不会开始计时。
- 真实 Hermes 读取隔离库并生成候选，未采用时不创建步骤。用户点击后才写入日计划。
- 刷新恢复卡片采用状态；完全退出测试应用再打开，旧对话仍在。真实 `session/load` 续聊回答出上轮动作，没有重复历史消息。
- 停止回复在 15 秒内返回；时间格点击预填对应时间；另一个窗口修改任务时显示冲突，保留输入草稿，用户核对后保存成功。
- 1440px 与 1060px 宽度无横向溢出。退出测试应用后，所属 ACP、Paper MCP 和记忆提供方子进程回收。

## 验收中修正

初次真实调用发现 Hermes 会话初始化还会发现全局 MCP，单用 `HERMES_ACP_SKIP_CONFIGURED_MCP` 不够。工作台增加仅在子进程内生效的配置过滤，并使用独立 MCP 名称，复测成功读到隔离数据。旧版 Inky 工具没有被模型调用，没有修改其源码或数据。

重启检查脚本的复选框断言曾等待已经消失的控件：点击核对会更新基准并收起冲突提示。改用点击操作，并补做现场检查，确认草稿保留、保存按钮可用、保存结果与输入一致。此处是检查脚本的等待方式问题。
