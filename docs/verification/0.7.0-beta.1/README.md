# Inky Paper 0.7.0-beta.1 试用版

按用户要求先交付试用版，完整 Coach 固定案例评测后移。此版本不代表 P1 全部验收通过，不发布远端版本。

## 包含的改动

今日步骤队列、旧安排处理、任务字段、明确讨论范围、可选择采用的计划调整、草稿恢复、批量改期、轻量收尾、原步骤继续、随手记整理、日预算与冲突、轻量项目与可纠正偏好，均包含在本轮代码中。M1—M4 分阶段隔离验收见 `docs/verification/p0p1`。

还包含 M5 已写入的总结依据、过时提示、原步骤交接，以及时长恢复和旧来源保护修复；这部分自动检查与真实验收状态分别记录，不把单元测试当作桌面或模型证据。

## 怎么试用

双击本仓库 `app/Inky Paper.exe`。首页底部点击「工作台」，安排今天的步骤；选择「设为下一步并回到 Inky」，点击 start 才开始计时。Coach 仍仅在你发送问题时调用，建议需要你点击采用。

优先体验：今天队列是否清楚、工作台返回是否顺畅、旧安排是否容易处理、不填反馈能否顺利收尾，以及每日记录/Markdown是否符合你的预期。

## 仍未验收

- C03总结在真实模型和最终桌面中的来源对应、冲突重读、多日回顾与下一步交接。
- 最终集成版的完整桌面回归，包括真实中文输入法、跨午夜、重启、断线、不同显示环境等。此前分阶段证据仍保留。

完整列表见 [M5待办](../../plans/p0p1/M5_PENDING.md)。本次不启动正式数据库做验收、不自动发送模型消息。

## 数据与恢复

继续使用 Paper 独立数据空间；首次打开旧格式库时，现有迁移逻辑先创建一致性备份。个人Markdown保持独立。打包本身不打开或修改用户数据库。

交付时保留旧exe备份；升级后若要回退，不能只替换旧exe后让其写新版数据。按 [数据升级与恢复](../../plans/p0p1/data-recovery.md) 保留数据库、笔记及升级后新增记录。

## 构建与检查

交付完成后由同目录 `release-manifest.json` 记录实际源码提交、版本、检查结果、exe SHA-256、旧exe备份和最终路径。此处不提前声称构建或复制成功。
