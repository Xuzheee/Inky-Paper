# C-03 总结来源与下一步

本包复用 `get_daily_record` / `save_daily_summary`，新增可追溯依据和只准备不执行的下一步。记录每类来源的保存时快照；正文是否忠于来源仍需真实模型逐句检查，引用合法不等于语义正确。

**阶段记录：以下是试用交付前的实现与检查快照。后续已包含在0.7.0-beta.1交付，真实验收仍待安排；当前待办见 [M5_PENDING.md](../../../plans/p0p1/M5_PENDING.md)。**

## 数据边界

真实读取登记 `(date, utcOffsetMinutes, dataVersion, notesVersion, sampledAt)`，存于当前 SQLite 连接的 TEMP 表，最多4096条，无笔记正文、无领域事件。新总结必须使用真实读取凭据和当前双版本；运行中计时按原 sampledAt 截断。个人笔记引用只能匹配同次读取的原文件正文。保存前再次核对笔记版本；文件系统不与 SQLite 共用事务锁，随后发生的编辑由过时标记提示。

相同已提交请求的原载荷优先返回，重启或个人笔记变化不使确认旧提交失效。相同 requestId 不同载荷拒绝。旧总结兼容空依据，不回填猜测的来源。用户本地旧格式保存保留兼容，Agent 新保存必须带 evidenceRefs；MCP 强制公开此字段并拒绝伪造 snapshot。

## 使用

每日记录可展开六类依据、读取截至时间及后续变化提示。「继续原步骤」核对当前完成/来源/计时状态，准备原步骤后回到 Paper；「为今天准备候选」重置到真实今天，仅预填问题。Markdown 同步来源快照与建议，不修改个人笔记。
