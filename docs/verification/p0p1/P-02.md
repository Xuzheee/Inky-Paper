# P-02 · 准备、安排与执行

Paper 显式选择统一走 `prepare_step`，从数据库恢复准确任务、步骤、首轮时长和日安排来源。默认今日便签和 start 使用同一个步骤，保留旧的用户明确选择；活动会话使用执行快照，浏览和迟到的选择事件不替换本轮。准备成功但读取结果失败时先禁用 start，只读恢复。

仅标题的旧任务由同一准备事务补出首个步骤；取消或失效的准备来源会阻止开始，用户需重新选择。原来“移除安排后默默降为未安排执行”的旧测试按计划安全边界调整。编辑同一步保留来源；进入工作时段确认页先显式准备，只有“开始工作并计时”才计时。`start_work` 新会话沿用准备来源，失效则整笔拒绝。

相关前端 99 项通过、类型检查通过；Rust 82 项通过、1 项历史基准忽略。新增事务测试覆盖仅标题准备、失败回滚、幂等重试、未来安排来源和取消后工作段/时钟零写入。Markdown 实际记录补原安排日期；自动检查验证未来来源和实际发生日分开。

原生桌面及跨进程恢复待 M1 集成验收；本包未运行模型。所有数据来自独立合成测试。
