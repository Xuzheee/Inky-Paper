# Inky 工作台

工作台是独立的原生窗口，用于安排任务、编辑日程和与 Hermes Coach 对话。现有 Inky 纸面清单、番茄钟和结束页继续承担执行。

## 打开

点击 Inky 任务首页底部、与 **随手记 · 足迹** 并列的 **工作台**，即可打开独立工作台窗口。也可以双击项目根目录的 **启动 Inky 工作台.cmd**，或在 Inky 系统托盘中选择 **打开工作台**。关闭工作台只隐藏此窗口，再次打开会回到原来的位置和对话。要完全退出，使用 Inky 托盘的退出菜单。

更新后若旧版 Inky 仍在运行，先正常结束或保存当前一轮，从托盘退出，再打开新版。

## 安排与修改

- 点击左侧日期，查看从这天起的三天计划；切换「任务 / 日程」查看相同安排。
- 点击「添加任务」，只填标题即可保存，具体步骤默认与标题相同。分类、优先级、截止备注/日期和完成标准可稍后展开补充。日期留空进入「待安排」；填写开始时间后出现在时间表中。
- 点击任务标题展开，选择「设为下一步并回到 Inky」，主窗口会选中对应任务与步骤，并带入首轮时长；点击 start 才开始计时。勾选只完成该步骤，父任务保持独立。
- 点击铅笔修改，或拖动卡片跨日、排序。日程中可以拖到新的时刻。键盘用户可通过编辑表单修改同样的信息。
- 工作、学习、个人事务、想法是分类。独立的「项目」用于关联目标、完成标准和参考链接，可以筛选、改名和归档；归档不删除任务或记录。
- 「待处理的旧安排」可以继续到今天、改期或放回待安排；操作会列出影响哪些安排。历史执行仍保留原来的来源。批量改期先生成预览，点击采用后才更新。
- 编辑草稿在关闭、重开后保留。源任务变化时先核对；保存结果未知时用原请求「核实并重试」，避免重复创建。

首轮时长是一次工作轮次的预计长度；日程时长是日历中为它预留的时间。两者都不是实际计时。修改安排不改写此前的执行记录。

## 当天时间、项目与偏好

当天的「全日预留」可展开查看预算与冲突。可投入时间留空表示未知，填写0表示明确没有可投入时间；没有估计的任务单独提示。预留总量相加，日历占用合并重叠区间，两者分别展示。不可用时段和任务重叠都会提示，不自动挪动计划。

「请 Coach 帮我取舍」只把问题放入输入框，发送后才调用。项目筛选不会把全日预算误当成该项目专属预算。

在「管理项目与偏好」中创建项目，填写可选目标、完成标准和参考链接。链接只保存，点击打开才交给浏览器；Coach 不把它当作已阅读资料。任务详情可关联或清除项目，原分类保留。

偏好由你明确保存，可限定为长期、某一天或某个项目，并能修改、停用或删除。每次请求读取当前适用版本；当天约束不会延续到其他日期，当前明确要求优先于旧偏好。删除只停止后续 Inky 请求使用，不表示历史对话、事件或其他提供方副本也被删除。

## Paper 执行与随手记

Paper 默认显示今天的步骤队列，也能进入全部任务或添加临时事项。`Do this` 和工作台交接只准备步骤，`start` 才计时；进行中、暂停或到时尚未保存时，不能偷偷换掉正在执行的步骤。

收尾可以完全跳过反馈。需要记录时，未完成优先问下次起点，完成优先问产出，明确选择卡住才问卡点。保存未完成后可继续原步骤；全部步骤完成后，父任务仍由你选择完成或保留后续。

「随手记整理」集中查看专注时收下的想法，可保留为笔记、关联任务或转换成新任务。原文、来源会话和转换关系保留；重复转换使用同一目标，不重复建任务。

## 每日记录与 Markdown

工作台中间可切换「任务 / 日程 / 每日记录 / Markdown」。左侧选日期后，「每日记录」和「Markdown」显示对应那一天，日期箭头按天切换；任务和日程继续显示三天。

- 「每日记录」汇总当天安排、番茄钟、手动完成和撤销、工作时段进展、随手记，以及已经请求生成的 Coach 总结。没有安排日程的实际工作同样显示。
- 「计划步骤当前已完成」表示计划中步骤的最新状态；「当日确认完成」按当天结束的番茄钟和手动步骤记录去重，同一天最后一次撤销会取消该步骤的完成计数。跨午夜番茄钟的完成归到结束日。工作和休息分别计时，暂停不计入。
- 任务和日程的日期下方展示当日完成步骤与工作计时，点击即可查看详细记录；日程卡片上的勾选和划线反映步骤当前完成状态。
- 「Markdown」直接显示已有文件的原文，可选择「当天记录」「个人复盘」「全部任务」。全部任务显示当前全局状态，不是历史快照。点击「打开原文件」使用系统文件关联打开；个人复盘可以在外部编辑，返回或等待几秒后重新读取。工作台原文区域只读。

任务和计时变化会触发同步，已打开的每日记录还会定期刷新；Markdown 页每 5 秒及窗口重新获得焦点时检查原文件。空白日期不会因查看而凭空产生记录。原始文档超过 2MB 时保留打开原文件入口，不截断后冒充完整原文。生成区原有的手改备份机制、个人笔记与任务数据库的边界继续沿用。

请求总结后，可以展开「查看依据」，检查保存时的会话、步骤、手动操作、安排变更或笔记原句。总结保留读取截至时间和来源快照；之后记录或个人笔记变化会提示尚未更新，由你再次请求才重读。旧总结不会补造依据。

总结的「继续原步骤」会核对当前状态，准备原任务、步骤和来源安排并回到 Inky，点击 start 才计时。原步骤已完成、来源取消或本轮尚未保存时会说明原因。「为今天准备候选」只切换到真实今天并预填问题，发送后才调用 Coach。保存总结同时校验记录与个人笔记版本，冲突需要重读；不会静默覆盖变化。

## 与 Coach 对话

右侧输入目标、卡点或复盘请求，Enter 发送，Shift + Enter 换行。只有主动发送时才调用 Hermes。可停止回复，通过「历史」打开旧对话或新建对话。

「安排一下 / 我卡住了 / 回顾一下」只预填问题。收起 Coach 保留输入与正在进行的回复；需要取消时使用「停止回复」。连接检查分别显示本机依赖、Hermes、Paper工具和模型状态，检查本身不连接模型；重试也先预填，由你发送。

右侧顶部显示讨论日期与步骤；未选择任务时讨论所选日期的计划与记录。点击范围旁的 × 可取消任务选择。切换日期或进入每日记录会清除旧任务范围。回复途中切换日期时，「本次回复」保留发送时的范围，「下次发送」显示新的范围；每条消息也保存当时的日期与步骤，重启后仍可查看。

Coach 的计划建议显示为候选卡片，可选择、修改动作和时长、调整顺序与日期。默认安排到发起讨论时的日期；如果明确要求安排到另一日期，建议会带入那个日期。采用按钮写明目标日期，浏览别的日期不会改变已有卡片；手动修改过的日期优先保留。没有日期信息的旧建议需要先选日期，不能自动当成今天。

点击「采用这一步 · 加入某月某日」才写入任务和日计划；采用不会开始计时。随后可点击「设为下一步并回到 Inky」。已有任务变化时，先核对界面提示的最新内容；已经加入目标日计划的卡片不重复要求核对采用。若当前番茄钟尚未保存，先回到 Inky 保存本轮，再选择下一步；普通「回到 Inky」入口不改变计时。

当前版本接入本机 Hermes 的模型与账户配置。工作台内还没有模型设置、附件上传、第三方日历同步；日程时间由用户在工作台中编辑。该工作台的 ACP 子进程不加载全局记忆、文件、终端或其他 MCP 工具，只提供当前 Paper 的读取、候选和按需总结；不改全局 Hermes 配置。

## 数据与连接

任务、步骤、计划仍保存在 `%APPDATA%\com.inky.paper\paper.sqlite3`。日程新增可空的 `startMinute` 和 `durationMinutes`，旧数据默认没有指定时刻。工作台编辑是带版本和请求标识的命名事务，未增加整份状态覆盖接口。

工作台可显示的对话另存于同目录 `workbench/conversations.sqlite3`，本工作台的 Hermes ACP 历史也隔离在其工作台目录。输入草稿、候选编辑与待核实的采用请求保存在本机 WebView 存储中；新增编辑草稿按数据库目录隔离。应用重启后可以恢复旧会话；模型的输出不直接作为任务数据库。

工作台打包了 Paper MCP 与 ACP 启动脚本，仍需要已安装的 Hermes Python 和 Node.js。默认查找 `Documents/hermes/venv/Scripts/python.exe` 或 `.hermes/hermes-agent/venv/Scripts/python.exe`，以及 `%ProgramFiles%/nodejs/node.exe`；非标准安装可通过 `INKY_PAPER_HERMES_PYTHON`、`INKY_WORKBENCH_NODE` 指定。

Hermes 会话创建还会发现全局 MCP，因此工作台进程在内存中过滤全局 MCP 配置，再显式连接当前 Paper 的工具。没有修改全局 Hermes 配置文件或其它 Inky 应用。Windows 进程组在退出或断开时回收本工作台启动的 ACP 子进程；实现参考 [Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

## 开发验证

先安装根目录和 `integrations/inky-paper-mcp-server` 的 pnpm 依赖。构建时将 MCP 打包并嵌入可执行文件，不依赖交付机器上的项目源码。直接运行 Cargo 时，build.rs 同样会执行这个打包步骤。

```powershell
corepack pnpm typecheck
corepack pnpm test:frontend
cargo test --manifest-path src-tauri/Cargo.toml
corepack pnpm tauri build --debug --no-bundle --config scripts/desktop/tauri-test.json
./scripts/desktop/launch-workbench-acceptance.ps1 -RunName workbench-check
node scripts/desktop/verify-workbench.mjs workbench-check
```

桌面脚本首先核对独立连接路径和空测试库，才创建测试任务。真实模型验收会在 Hermes 中产生验收对话，Paper 测试任务保存在独立目录。`verify-workbench-resume.mjs` 用于同一隔离数据目录重新启动应用后的续聊、取消、日程表单和冲突检查。
